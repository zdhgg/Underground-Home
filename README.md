# 地下小家园（Underground Home）

面向 7 岁儿童的 2D 横截面地下家园建造与探索游戏：地表风暴迫使小伙伴搬入旧避难所，玩家通过自由挖掘、修复设施、建立地下生态，把避难所逐渐变成温暖、能运转的家园。

技术栈：**Vite + Vue 3 + TypeScript + PixiJS + Vitest**。

## 后续开发的交互原则：当前焦点只有一个

任何新角色、新建筑、新任务都遵循：**一个主要关注对象，一个主要推进操作，明确交接给下一步**。出场先让玩家看清对象，再就近对话；进入建筑详情后只展示当前建筑；对话或施工期间，任务建议退场。帮助只解释当前一步，其他工具通过次要入口查看；关闭、取消、撤销和楼层导航仍可使用，玩家可以暂时离开主线自由建设。

实现与审查要求以 [AGENTS.md](AGENTS.md) 为准。主要情境面板使用 `data-attention-panel`，主要推进按钮使用 `data-primary-action`，由 [界面交互契约测试](tests/attention-contract.test.ts) 检查多状态同时到达及关注对象切换时，实际舞台最多出现一个主要面板、一个主要推进按钮。新增交互必须补相应情境；不能只测试一个返回值为“当前焦点”的变量。断言保障可计算的结构，镜头是否抢回、话语是否贴近对象、是否遮挡角色和视觉强调是否冲突，还要通过桌面/窄屏实景检查。

首轮落地的行为、截图与验证见 [首间小窝交互验收](docs/acceptance/focus-ux-v1/README.md)。下文保留版本与历史阶段记录；与此原则冲突的旧界面描述不作为后续交互设计依据。

第二层的泉边灶台、围坐餐桌、泉边小菜园与休息角已统一为手绘石拱洞室：地图与建造卡共用分层图片和布局；菜槽保留四个生长阶段，休息角复用客厅美术。新增素材、内置 ImageGen 提示词、真实页面及验证见 [第二层设施美术验收](docs/acceptance/water-facilities-art-v1/README.md)。

## 已发布版本：v0.2.0 · 首次突破岩层与第二层家园

v0.2.0 以 v0.1.0 为基线，在 `codex/first-spring-breakthrough` 上实现：安好小床 → 挖到岩壁裂纹、听见滴水 → 换小铁镐 → 挖通梯道 → 阿土沿梯子下到第二层 → 开路找到天然泉水 → 自由扩挖、安壁灯。两处突破口适配不同首层舱位；坚硬基岩继续不可挖。第二层维持连续横向空间，不增加第三层。

操作定位（本轮收口）：**玩家是建设者，只指定目标，阿土自己执行**。普通泥土点一下就直接挖开；带裂纹的岩石是"施工委托"——阿土沿真实通道走到那一段上方挥镐，落镐那一刻才破开并接长木梯；还没换铁镐时点裂纹，他会走过去听水声；露面的泉水同样是他自己走到水边才算发现。点击已经挖空的空地不再移动阿土。

破岩节奏（本轮优化）：前两段各点一次学会指挥，从第三段起面板出现 **「⛏ 一路挖到底（还剩 N 段）」**，点它或继续点裂纹岩都会一口气挖到洞底——每一段仍然是真实走位 + 挥镐 + 梯子接长，只是不用再重复点击。打通岩层、第一次下到第二层、发现泉水各有一次里程碑卡片、镜头变化和轻量提示音（WebAudio 现场合成，不联网、不加素材）。

施工中断（本轮修复）：切到后台、画面被冻住（窗口被系统遮挡/帧被暂停）时，进行中的委托会**安全取消**——世界保持原样、阿土回到记录位置、输入立刻解锁，回到前台还会补一句"怎么接着来"；慢但在动则不会打断。窗口失焦只复位指针手势，不再出现"点不动"的锁死。

试玩：`npm run dev -- --host 127.0.0.1 --port 5174`；生产验证：`npm run build`，再运行 `npm run preview -- --host 127.0.0.1 --port 5174`。

v0.2.0 只写 `underground-home-spring-playtest-v1`、v13 格式。新试玩可点“复制 v0.1.0 进度”，只读旧双层库并另存；同一浏览器、同一网站来源（协议、主机、端口相同）才能找到该来源下的旧档，不自动扫描其他来源。首次开始挖掘后收起复制入口，避免覆盖正在玩的新进度。旧双层库和更早正式库均不被写入。

验证：**361 项测试通过，类型检查与生产构建通过**；突破流程完成浏览器全流程（含逐段委托、一键连挖到底、突破与抵达里程碑、发现泉水、画面冻住时的自动解锁、刷新恢复、壁灯选址与撤销）。实施范围见 [突破岩层决策](docs/FIRST_BREAKTHROUGH_SCOPE.md)、[施工委托决策](docs/BUILDER_ORDERS_SCOPE.md) 与 [第二层体验优化决策](docs/SPRING_UX_SCOPE.md)，实景与复现步骤见 [泉水探索验收](docs/acceptance/spring-v1/README.md)、[施工委托验收](docs/acceptance/builder-orders-v1/README.md)、[第二层体验优化验收](docs/acceptance/spring-ux-v1/README.md)。v0.2.0 的版本号、标签与发布记录见[发布说明](docs/releases/v0.2.0.md)。

## 原有玩法基线：P2 M2 伙伴入舱与休息

选址沿用 M1：点亮核心后选“睡眠舱”，点一下想放小床的地面，就会以点击格为舱体底边中心显示预览；预览旁的短句和绿／红轮廓会说明能不能建。选中后可以再点别处换位置，点“确认建造”落位，点“取消”或再点“睡眠舱”退出。舱底仍要有实心地面，侧门连通家园；不能压住核心、入口或堵住已有舱门。左侧能源石旁、右侧软土都可自由选址，没有固定建造点。粗版不消耗建造资源。

本阶段只开放第一间睡眠舱：建成后建造工具收起，避免出现无人使用的空舱；撤销后工具恢复。建成后伙伴先“准备入睡”，再沿实际挖通的空洞通道走到舱门；遇到高度差时贴着岩壁攀爬，不穿过泥土 / 岩石，也不悬空漂浮。两位伙伴都钻进被窝后才播放庆祝反馈和“睡着啦”；在那之前任务面板仍停在“睡眠舱”这一步并显示“准备钻进被窝”，伙伴躺下后才显示 4/4 和“睡得好香”。重新载入存档时伙伴直接处于睡眠状态并继续呼吸起伏，不重播入场。

入舱路径是建成时计算的一次性演出，不含寻路系统或居民AI；“撤销”支持撤回本次会话的建设和挖掘。存档仍为v3，伙伴的睡眠状态不写入存档，由第一间睡眠舱推导；v1 / v2自动迁移并保留原地图及点灯进度。睡眠舱任务按实际设施判断，拆回后会回到待建设状态。

造型暂用程序化示意：伙伴休息时有被子、闭眼和±1.2px呼吸起伏。现有104项测试通过，生产构建通过。本地浏览器操作被Work设置禁用，本轮尚未完成浏览器试玩或截图；请重点试玩入舱路径、贴墙攀爬观感、两人错峰入舱和刷新后的睡眠恢复。

  - 地图高亮当前目标区域（线索，不代替挖掘；小鼹鼠只给一个问题和一个真实目标）；
  - 当前主线四步：挖开泥土找到能源石 → 收集能源石 → 修复能源核心 → 自由选址安置睡眠舱；
  - 睡眠舱入住：建成后伙伴沿实际通道入场，爬高差时贴墙攀爬，钻进被窝后才庆祝；刷新后直接恢复睡眠，不重播入场；
  - 修复演出：核心启动闪烁 → 顶灯一盏一盏依次亮起 → 伙伴撒花庆祝 → 镜头自动拉开展示点亮后的家园；
  - 挖错撤销：LIFO 撤销；已挖开的能源石不会被"撤销"埋回去（避免任务状态矛盾）；
  - 带版本号的 IndexedDB 自动存档与恢复（v3，含 v1 / v2 旧档自动迁移）；损坏存档降级不白屏。
- 尚未实现（后续阶段）：睡眠舱精修、泉水、水培温室等，详见 `docs/PHASES.md`。

## 已知限制（P1.1 范围内）

- 人工试玩验收待完成（选址手感、入舱路径是否自然、贴墙攀爬观感、刷新后睡眠状态）。
- 左侧舱门通常比避难所地面高2格，伙伴会贴着左壁爬上去，目前没有专门的小梯子；如果试玩觉得别扭，可在后续补一个梯子 fixture。
- 只服务第一间睡眠舱；多舱入住、镜头跟随和 Zzz 等睡眠提示留到后续体验收口。
- 撤销栈只保留本次会话的挖掘和建造记录，刷新页面后不能撤销刷新前的操作。
- 暂不支持双指捏合缩放，多指手势留待后续阶段。
- IndexedDB 不可用时，进入页会直接说明“这个浏览器不能保存进度”，游戏仍可玩，但刷新后从头开始；不会假装已经存上。

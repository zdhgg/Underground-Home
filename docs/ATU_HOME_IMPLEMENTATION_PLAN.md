# 阿土探索与房间家园：分阶段实施方案

日期：2026-10-18。修订：v3，纳入功能先行的房间建设调整。状态：**第1至4阶段及本次房间流程调整已实施，待玩家试玩；第5阶段未启动。** 验证见[房间建设调整](acceptance/room-construction-v1/README.md)、[第1阶段](acceptance/atu-control-v1/README.md)、[第2阶段历史记录](acceptance/rooms-v1/README.md)、[第3阶段](acceptance/partner-work-v1/README.md)、[第4阶段](acceptance/adeng-light-v1/README.md)。

> 用户后续批准：建房时先确认功能，据功能确定大小和容量，放蓝图后由阿土逐格挖掘，再确认建成；基础设施由房间安排，之后通过扩建提升容量。房间后侧为设施、前侧为通道。此决策替代本文第2阶段的旧入口和下文“挖空间、划用途、放设施”的历史描述；具体范围以[房间建设决策](ROOM_CONSTRUCTION_SCOPE.md)为准，未启动个人床、厨房或共同生活阶段。

依据：[项目规则](../AGENTS.md)、本轮讨论、[伙伴成长决策](PARTNER_PROGRESSION_DESIGN.md)。本方案承接已完成的伙伴互动首版，不重新实现角色美术和阿土小铁镐。

## 1. 本轮确定的方向

- 玩家主要操控阿土，探索、观察和突破由他串联；鼠标可完成全部核心操作，触屏沿用点按与拖图。键盘不是首阶段前提。
- 点泥土是施工指令：阿土走近、找落脚点、动手后才挖开一格。玩家无需先点空地站位，地图不再隔空即时删土。高处采用有限触及范围和一格短踏台，不能无限向上挖。
- 不设四人自由切换栏。其他伙伴通过专业工作参与营地，不要求玩家反复选择人物。
- 自由建设是核心：玩家决定空间、用途、位置与推进时间。剧情提供一个当前悬念，不要求先领取任务。
- 四位伙伴不必始终同屏。阿土位于探索前线，其他伙伴围绕住处和设施停留；一次只强调一位角色和一个主要反馈。
- 房间是嵌入岩层、由通道和梯道连接的洞室。玩家挖空间、划用途、放设施；没有强制的每层功能分区和固定房型拼图。
- 独立卧室、厨房、活动室是后续扩建目标，不是开局必须补齐的设施清单。
- 升级改变实际能力，帮助解决扩建问题；不加入挂机经验、饥饿惩罚、每日照料、战斗或复杂居民AI。

## 2. 当前基础与需要调整的旧决策

| 已核对的现状 | 本方案的处理 |
| --- | --- |
| 四位图片角色、点击聊天、阿土换镐及裂纹施工已实现 | 保留并复用，不再作为新阶段成果重复计入 |
| 旧施工委托决策明确规定“空地不移动”，普通泥土立即挖开 | 第1阶段恢复空地移动；普通泥土改为阿土走近动手后挖开。保持一次指令一格，不自动连挖普通泥土；相邻施工尽量复用站位 |
| 阿土主要在裂纹探索后作为探索角色出现，建床后通常休息 | 第1阶段统一为一位可主动探索、保持待命的阿土；保留他的床位和其他伙伴休息表现，不出现床上与探索中两个阿土。主动睡觉操作暂不扩展 |
| 其他伙伴主要站大厅或睡在床上 | 第3阶段才增加设施旁停留及玩家触发的专业工作；不提前承诺自主生活模拟 |
| 地图44×28；首层两翼净高3格，软土与硬岩边界固定 | 第1阶段先验证三格层高中的地面/向上挖及短踏台；第2阶段房间沿用现有建设带。不扩图或开放全部岩石 |
| 现有双人睡眠舱3×2；菜槽一格；种植和睡眠舱主要限首层 | 先做可包容现有设施的房间区域；保持原限制，不把新增房间当作跨层建设解锁 |
| 既有床位按稳定伙伴ID映射，存档版本为v7 | 独立卧室和自由分配床位另在第5阶段迁移；新增持久状态时逐阶段升级版本 |

批准后，实施阶段须同步更新被替代的操作说明，例如[施工委托决策](BUILDER_ORDERS_SCOPE.md)中的“空地不移动”和“普通泥土立刻挖开”。历史文档保留原记录，并标明被哪一条新决策替代。v1草案中“保留普通泥土即时挖开”的建议由本修订替代。

## 3. 阶段与依赖

| 阶段 | 交付后玩家得到什么 | 前提 |
| --- | --- | --- |
| 1. 阿土移动与实际挖掘 | 点目标即可走近施工，头顶和三格高处有合理挖法，镜头与输入清楚 | 现有互动首版 |
| 2. 房间基础 | 能把自由挖出的空间布置成住处、种植区和公共区域 | 阶段1通过试玩 |
| 3. 伙伴在房间里做事 | 在合适位置找到伙伴，点击设施让对应伙伴执行真实工作 | 阶段2房间与通路稳定 |
| 4. 第一条专业能力成长 | 以阿灯照明为候选，让升级真正改善扩建区域 | 阶段3至少一条工作闭环通过试玩；能力范围单独确认 |
| 5. 个性住处与共同生活 | 可逐步建四位的独立住处，再增加有真实活动的公共房间 | 阶段2、3稳定；各子项单独确认 |

阶段4与5不必机械串行，按阶段3试玩结果决定先做哪一个。本方案不是一次批准后自动把所有内容铺开；推荐先批准阶段1，后续逐阶段验收并启动。

## 4. 阶段1：先让阿土成为能操作的主角

### 玩家操作

| 输入 | 结果 |
| --- | --- |
| 点可到达空地 | 阿土沿真实通道走过去；点击较高空洞只解析到该位置下方合法落脚点，有预览反馈，无合法落脚点就提示 |
| 点松软泥土 | 立即标出所选一格和施工方式；阿土自动走到可达施工位置，动手接触土面后才挖开该格。无需先手动移动 |
| 点裂纹、泉水等已开放探索目标 | 自动选择可达操作点，由阿土走近并观察或施工，不要求先手动站位 |
| 点伙伴 | 保留短对话；至多一个主要操作 |
| 拖动 | 只平移地图，不移动阿土、不挖掘 |
| 建造模式中点地图 | 只选址，保留预览、确认、取消 |
| Esc或明确取消入口 | 退出当前界面/选址，或取消尚未完成的移动与施工；优先级明确，一次只退出当前最上层状态 |

裂纹施工与普通移动冲突时按“探索目标优先、空地移动其次”处理；已挖空梯段原来的继续施工容错必须用实际浏览器检查，避免点梯子既被判移动又开挖。

### 普通挖土与高处施工

一次指令解析为“目标格 → 可接触的土面 → 合法施工位置 → 路径 → 施工动作”。先判断地层与工具权限，再判断可达性，最后执行；在落爪/落工具的时刻复核并只修改这一格。软土保留爪挖表现，裂纹岩复用换镐后的施工，不能提前用普通挖土绕过小铁镐解锁。

| 情况 | 规则和反馈 |
| --- | --- |
| 身前或较低的土 | 走近侧面挖，优先复用当前站位；不挖掉自己依赖的承托 |
| 工具或爪子可触及的头顶土 | 保持合法站位，抬手向上挖；命中点在实际土面，不能无限延伸动作 |
| 三格层高中地面够不到的顶部 | 使用一格高短踏台：走到可达摆放点 → 展开 → 登上 → 挖所选一格 → 按需收起。踏台计入实际触及与支撑判定，不是只播放动画便远程挖土 |
| 土藏在另一块土后面 | 不穿土触及；标出前方挡路处，短句提示“先挖开这里”。不偷偷替玩家挖掉前面的格子 |
| 无路、无支撑、身体或踏台上方净空不足 | 保留目标预览并提示原因，不修改世界，不让阿土卡进土或设施 |
| 超过踏台可覆盖的高度 | 提示“这里还够不到，需要施工梯”；首版不提供通用施工梯建造，也不为此放开硬岩。原有上下层梯道继续有效 |

触及范围以规则中的有限范围和渲染中的手/工具落点共同校准。首版目标是覆盖现有三格建设带：地面施工处理近处下两格，短踏台补足顶部；只在路径、土面暴露和净空都成立时可挖，不能仅按“在同一列”放行。先用三格土墙实景验证动作与尺寸，再接完整流程。

短踏台是随身施工用具，不新增资源、经验或手工摆放菜单；只能放在已挖通、有承托、路线可达的地方，不跨洞、不重叠设施、不堆叠，不阻断既有通路。可以在同一位置连续施工时复用，离开时收起。起身、收起、取消和刷新后回到踏台旁的真实安全落点，不把临时踏台作为永久地形或半空存档位置。

泥土开挖方向由玩家决定，不强制照一份房间蓝图挖；但要从可接触土面逐步拓展。挖通一格低洞不等于阿土身体能钻进去，移动和摆踏台都检查实际身体净空。若先挖底部，仍可在原位置清出相邻上方土，形成足够通行的洞口。

### 节奏与指令替换

- 点击立即出现所选格、落脚点或失败原因，不能等阿土走到后才告诉玩家不能挖。
- 一个普通挖土指令最多改一格；不加入拖挖、自动清空整片、普通土长队列。原裂纹“一路挖到底”保留既有适用条件。
- 已在可用施工位置时直接动手；附近下一格尽量原地或短距离调整。初版短踏台展开和单次普通挖掘的额外动作以约一秒内为调校目标，不把较远走路时间伪装成瞬移。
- 重复点同一目标不重启动作、不重复结算。落爪前点新施工目标或空地可替换指令，先从踏台安全下来；已发生的一格效果保留，再处理新目标。
- 玩家可继续拖图看家园；当前施工目标离屏不取消、不额外强拉镜头。“找到阿土”只定位镜头。

### 实施范围

- 统一阿土在大厅、睡眠舱和探索中的身份、位置来源及显示，不生成重复角色。旧档中未开始探索的位置须有合法初始化办法。
- 移动目标、施工位置、短踏台摆放点和不可达原因可见；路径遵守地面、真实梯道、身体净空、设施占地和地层限制，不穿墙、不飞行、不跳跃。
- 已有阿土合法站位时，只从该站位寻路；禁止因为当前路不通就改从大厅起点开始演出。大厅起点回退仅用于旧档或新开局首次初始化，并核查其合法性。
- 纯移动可以点新目标重算；施工采取“当前已完成效果保留、未发生效果不执行”的取消边界。取消、失焦、切后台和重新载入不能重复落镐或永久锁输入。
- 手动拖图暂时交还镜头控制；阿土每一次新行动（走动、跨层、施工）开始都重新拿回跟随：长距离 / 跨层走位把镜头中心带过去，短走位只在贴近视野边缘时轻推。同一趟行动里玩家拖图或缩放，镜头立即让位到该趟结束。保留“回到家园”，新增简明“找到阿土”入口，镜头定位不瞬移角色。
- 当前角色只有阿土需要轻量选中标记；其他伙伴名字改为指向、点击或首次加入时显示。保留单气泡反馈。
- 调整位置存档校验：移动后的合法首层站位也能保存恢复；不再把所有探索角色位置都绑定到已发现裂纹。若需持久位置新结构，提供v7迁移；不把短暂移动状态存成已完成行动。
- 撤销挖土时若会埋住阿土，先沿真实路径退到相邻安全位置再恢复；无安全退路则解释原因并保留世界和该撤销记录，不通过瞬移或丢记录处理。既有唯一通路与设施保护仍有效。
- 维持地图、已挖地形、床、菜槽、供水、送电和工具的原有效成果。旧档已挖空间不回填，不要求重做探索。

内部实施顺序为：1A统一阿土位置和行动取消；1B普通挖土的可达土面、向上动作和短踏台；1C旧档迁移、撤销及完整首章回归。这是同一阶段内的开发顺序，不把缺少高处挖法、无法推进初始能源石的中间状态作为完整交付。

### 验收

1. 新开局不必先发现裂纹，就能用鼠标指挥阿土移动。
2. 点可接触泥土后，阿土从当前真实位置走近，动手才改变一格；不可达、不暴露或硬岩目标不能隔空挖开。
3. 三格土墙的低处、头顶、顶部能分别通过地面挖、向上挖、短踏台处理；踏台不悬空、不堆叠、不穿顶，工具/爪子实际碰到土面。
4. 从新开局连续完成找到能源石、修核心、自由选址建床、听水声、换镐、打通梯道及发现泉水，避免新触及规则把主线堵死。首层左右翼及已开放泉水层都检查扩挖。
5. 点击和拖图、角色交谈、普通挖土、建造选址互不误触；原裂纹快捷连挖仍可用。重复点击不重复施工，改目标不瞬移、不叠加多份行动。
6. 移动中、踏台展开/登台/施工/收起中分别取消、切后台及刷新，均不重复改地形、不悬空、不锁输入。撤销不埋角色、不丢待撤销记录。
7. 旧v7档的床、镐、水、电、菜和已发现地点完整保留。移动后新档刷新可恢复，非法位置加载有反馈，无重复阿土。
8. 生产构建和相关自动测试通过；桌面、900×620横屏及触摸点按/拖图检查有截图和操作记录。自动化记录与真实儿童试玩结论分别注明。

### 本阶段不做

房间系统、三位专业工作、键盘WASD、多角色切换、跳跃、长指令队列、额外地层或地图扩张。不加入通用施工梯、脚手架搭建或土体坍塌模拟。玩家不用先手动把阿土走到目标旁边，但实际挖掘必须由阿土到达合法施工位置后完成。

## 5. 阶段2：房间是自由空间的用途，不是固定房型

### 首版三类空间

- **住处**：复用现有睡眠舱作为房间内的设施，允许共同睡眠区。
- **种植区**：复用菜槽与现有供水条件，有菜槽才有种植功能。
- **公共区域**：大厅/客厅用途，首版用于简单休息和共享空间，不声称已有聊天聚会模拟。能源核心保留原位及保护范围，用地面、光色和设施表现发电设施区，暂不另造一套发电机系统。

### 建设流程与规则

流程为“挖出空间 → 选房间用途 → 点位置预览 → 确认 → 按需放设施”。首次建床可自动给出创建住处的可跳过建议，直接放床的旧方式仍可用。

- 首版以一段已挖通的地面空间定义区域，默认尺寸适配现有层高。通过预览上的简明增减宽度按钮调整，不用拖框，避免与拖图冲突。
- 第2阶段实际落地：只在暖窝层规划，宽度3至9格；创建时按已挖洞室自动适配两格或三格高度，修改已有房间时保留原高度。旧睡眠舱上方可能仍有泥土，不强制清出三格或拆床才能划房间；没有自动开挖或扩大建设带。
- 房间有稳定ID、范围和主要用途。范围不包含未挖土和硬岩，不覆盖关键通道/地标保护区，房间区域之间不重叠。核心占地区域仍按原规则保护。
- 房间的主要用途只帮助识别和布置，不禁止玩家在住处旁摆菜槽，也不因为改房间名字就改变实际水电、床位或产出。不同用途的混合空间可以保留。
- 门框、地面和小标牌用于分隔，首版不作为新的实体障碍；不要求密闭墙、门数量、精确面积达标，不模拟承重、氧气或通风。
- 不自动把整片连通洞穴认成一间房。玩家确认范围，房间能调整或移除；移除区域标记不会删除其中设施，撤销需连同相关引用保持一致。
- 没有设施的区域只是预留房间，不能凭标记获得床位、供水或额外产量。未被房间包裹的旧设施继续正常工作。
- 旧档不改地图、不挪设施、不把全部大厅硬套进一种房型。可以从旧设施给出可选区域建议，用户确认后才保存房间。

### 验收

能在左右不同位置建成房间、改变宽度、取消及撤销；房间之间能通过真实通道相连；名称与边界缩小时不遮挡设施。标记和改用途不改变原功能规则，旧档设施无需补建房间仍能使用。范围、占用、保护、撤销和存档迁移均有规则测试与浏览器检查。

本阶段不替换双人舱、不强制四卧室，不开放深层卧室或种植，不新增厨房烹饪、设施生产链和一批纯装饰房型。

## 6. 阶段3：伙伴在设施旁生活，点设施就能协作

先选设施工作点，再决定伙伴停留位置；不按固定屏幕坐标把四个人塞在大厅。各子步分别实现和验证，不同时改全部资源规则。

| 子步 | 可玩的闭环 | 保持的边界 |
| --- | --- | --- |
| 3A. 小满与种植区 | 点击成熟菜槽 → 小满从合法停留点走到操作位置 → 收获时作物与食物真实变化 → 一句反馈 | 复用现有生长和收获；不新增浇水打卡、真实时间等待或第二次确认 |
| 3B. 小泉与供水 | 玩家发起现有接水操作 → 小泉到对应操作点参与接通 → 原供水状态与画面变化 | 复用真实上下层通路；不让阿土继续替小泉全程做水路工作，不新增水量模拟 |
| 3C. 阿灯与照明 | 玩家确定合法壁灯位置 → 阿灯到操作点协助点亮 → 原壁灯和照明实际生效 | 已有壁灯与电力成果保留；不因阿灯未到场熄灭原照明 |

- 玩家始终主要指挥阿土；专业工作由设施目标自动分配伙伴，不切换当前主角。
- 提供各自的设施侧边停留点和住处回退位置，避开通道与点击热点；没有设施时使用合法公共区域。旧档伙伴不能因已入床而永远无法参加工作。
- 首版只做玩家触发的一次动作和简单停留/返回，没有自主任务规划、作息排班或持续模拟。
- 复用短路径表现，不能穿墙、绕过未开放岩层或瞬移到工作点。走不到就说明原因，并允许修通道路或改目标。
- 连点同一设施不能重复扣资源、重复收获或开出多份工作。首版最多一项专业工作，显示当前操作者和取消入口；是否允许与阿土移动并行，以实际状态和撤销安全为准，不预先加入多人任务队列。
- 每次操作最多强调一位伙伴。名字按需显示，气泡不叠加，镜头不为了营地工作把正在探索的玩家强拉回去。

验收重点：孩子无需先选人即可完成真实工作；动作与效果对应，取消和刷新不重复结算；四位各在合适位置，无须同屏也能找到。每个子步都回归房间、通路、旧档、撤销及已有阿土施工。

第3阶段落地：三项工作分别由小满、小泉和阿灯执行，效果在动手时结算；小泉接管后沿通路返营地，另两位在设施旁待命。伙伴保留床位，改为可工作站位；有旧设施时优先选设施旁合法位置，否则使用公共区域/大厅。新增收起式“伙伴在哪”入口，仅找镜头，不切换控制。首版一项工作期间暂停阿土新指令与建设、撤销，允许拖图、缩放、找伙伴和取消；没有任务队列。建床需要伙伴让位时先走到安全处再建，取消不继续建床。存档v10保存逐格到达的位置，不保存工作队列或半段动作。完整结果见[第3阶段验收](acceptance/partner-work-v1/README.md)。

## 7. 阶段4：一次只做一条专业能力升级

推荐首先评估阿灯照明，因为扩建区域偏暗与当前地图直接相关，效果容易观察。

候选闭环：“发现一处已开放但较暗的扩建空间 → 阿灯提出改进 → 玩家主动选择 → 获得扩大定点照明范围的实际能力 → 在该空间使用 → 房间明显变亮”。具体解锁来源、范围、操作点和与壁灯的关系须在阶段3完成后用小方案确认，再进入编码。

升级不回收已有光源，不以更强光为由打开未发现的地层，不制造新增人口后的强制缺电；暂不新增升级材料或经验。使用稳定`abilityId`和`upgradeId`，只有一个持久状态来源。

验收为：同一空间升级前后差异可见、实际照明规则变化、已有灯光不退化、重载后能力保留、无法反复升级或重复消耗。不做只有“等级+1”的按钮。小满和小泉的进一步升级仍是后续候选，不随此阶段自动开发。

第4阶段落地：[阿灯聚光灯罩小方案](ADENG_LIGHT_UPGRADE_SCOPE.md)。找到泉水、给下层送电并装过普通灯后，如果出现可达的照明缺口，阿灯提供可忽略建议。主动学习一次后，点旧灯由阿灯到场加装，或安装带罩新灯；逐格覆盖从左右各2格扩大为各4格，暖光按已挖通空间计算，遇土岩截断。保留原灯圈和基础亮度，光不会解锁地层。加装可撤销，学会的能力保留；v11保存升级ID和逐盏灯配置，兼容v10旧成果。完成工程检查及桌面/触摸验收，详见[第4阶段记录](acceptance/adeng-light-v1/README.md)。

## 8. 阶段5：独立住处与共同生活，分项扩展

### 5A. 个人住处

允许从共同睡眠区逐步扩建为四位各自的住处。以稳定伙伴ID分配真实床位，既有双人舱不拆除、不失效；单人床作为新增选择，需要独立占地、通路、撤销和存档规则。角色通过一两件辨识物体现性格，首版不做大型家具目录或满意度数值。

与旧床位固定映射不同，入住分配改为显式数据，采用版本化迁移。新增伙伴通过定义接入，不把“只有四位、只能四间”写死。四间卧室是可选成果，不是通关门槛。

### 5B. 共享用餐与厨房

先做“食物来自种植区 → 玩家发起一起吃饭 → 伙伴在可达餐点集合 → 消耗一份已有食物并反馈”的最小活动。厨房只有在存在明确备餐行为后再加入，不先造空壳房型，也不加入反复点菜谱、食材搬运和饥饿倒计时。

### 5C. 客厅与活动室

有可观察的共享活动再扩展，例如短暂聊天、分享发现。优先复用公共区域，明确和用餐、休息的区别；如果功能重复则合并，不单独增加一个菜单选项。

每项分别审定玩法与美术范围，并检查真实通路、集合/解散、取消、伙伴加入条件和已有布局。地图容纳不足时再提交空间扩建方案，不偷偷放开全部岩层。

## 9. 工程边界与存档策略

- `core`管理位置可达性、施工土面、有限触及范围、踏台支撑净空、房间范围、设施占用、工作结果与升级条件；纯规则不引用Vue/Pixi。
- `input`区分点击、拖图和取消；优先级由明确的模式与目标解析决定，不在多个组件各自抢事件。
- 会话层协调单次动作、取消、保存和反馈。移动、普通挖土与踏台施工、专业工作状态拆成小模块，不继续把所有规则堆进`session.ts`或渲染器。
- 渲染层展示角色、路径、房间边界与动作；动画回调按单次行动标识核对，过期回调不得重复修改世界。
- 房间和设施分离，伙伴与床位引用稳定ID；存档只保存必要成果与位置，不保存半段动画。新版本保留地图、床、水电、作物和工具的既有成果。
- 每阶段独立确定实际新增字段与版本；不提前宣布所有阶段共用某个固定新版本。继续使用现有试玩存储隔离，加载失败不覆盖原档，不以重开游戏代替迁移。
- 新增撤销项须检查设施、房间引用、可达站位和工作状态，不能把角色埋进土里或断开唯一通路。

## 10. 每阶段交付、验收与批准边界

每阶段开始前说明当期范围与替代的旧行为；仅实施已批准阶段。交付包含变更文件、真实执行的`npm test`及`npm run build`结果、生产预览浏览器检查与截图、存档兼容检查、已知限制和可回退方式。

界面至少检查正常桌面和900×620横屏；如宣称触屏支持，另检查触摸点击/拖动。自动化验证与真实儿童试玩分别记录，不以自动脚本替代孩子是否理解操作的判断。

阶段1试玩先判断“能否直接点目标让阿土挖，并理解高处为什么用踏台”；阶段2看“能否自主建成一个想要的房间”；阶段3看“能否说出每位伙伴帮了什么忙”。出现明显理解或操作问题时，先收口当前阶段，再申请下一阶段。

本方案首次提交时只新增文档和入口链接；用户随后逐阶段批准实施第1至4阶段，均已完成工程实施与自动检查。**第5阶段仍为后续路线图，尚未启动，各子项仍需单独确定范围。** 真实儿童试玩结论不由自动检查替代。

# 设施面板框架与菜园试点（S2）决策

> 日期：2026-10-24。分支 `zcode/facility-panel-v1`，基于 main `06e996d`。
> 上游依据：分阶段实施方案 S2 批次；设计基线 §7.3（设施表）、§6.4（协作原则）。

## 解决的问题

建筑"建成之后"没有交互面：灶台、餐桌、菜园本体点不出任何东西；点未熟的菜只有一句文字（死交互）；想让菜长熟必须去干别的事。设施动作和未来的"升级"缺一个可扩展的落脚点。

## 决策

1. **设施表（交互层）**：`src/app/facilityPanel.ts` 声明每个设施的标题、状态摘要、主要动作（谓词 + 标签 + 派发目标）与次要入口。第一批接入：泉边小菜园、泉边灶台、围坐餐桌。
2. **三条护栏（验收标准）**：
   - **面板只指挥伙伴执行**——收菜/浇水按钮派发 `requestPartnerWork`，小满沿真实通路到场；不直接改数字。
   - **直点快捷路径保留且共用同一结算**——点熟菜仍直接收；点未熟的菜从"一句提示"升级为"直接派小满浇水"；面板与直点同一套 `harvestPlanter` / `advancePlanters` / `serveMeal`。
   - **本批次不出现"升级"入口**——升级入口留给 2C（育苗架）等内容批次，且必须是新动词。
3. **浇水是新工作类型**（`partnerWork` 的 `watering`）：小满走到菜旁，结算时所有未熟菜各长一档（复用 `advancePlanters`，与"干活长大"同一推进函数、不叠加；熟透的不长）。照料取代了"挖土催熟"。
4. **开饭三入口同一结算**：引导主按钮、折叠抽屉旧按钮、灶台/餐桌面板主操作全部走 `startMeal → serveMeal`，一次只扣一份食材。
5. **面板让位规则**：设施面板 `data-attention-panel="facility"`；打开时引导退场，被对话/施工/工作/施工状态接管时关闭；点别处收起、拖动地图不收起；Esc/取消可关。

## 边界（不做）

- 不迁移住处扩建、泉水接水、客厅、壁灯的现有入口（后续按需）。
- 不新增存档字段、不改存档版本（面板状态全部由世界数据推导）。
- 不做升级、装饰、多选菜；菜园面板状态图示覆盖全部菜槽（含自由摆放的）。

## 实施结果

- 新增：`src/app/facilityPanel.ts`（设施表 + 面板控制器）、`src/components/FacilityPanel.vue`；`src/core/partnerWork.ts` 增加 `watering`；`src/render/partnerMotion.ts` 浇水动作配色。
- 集成：`session.ts`（点按开面板、直点浇水、让位与派发、`startMeal` 抽取）、`App.vue`（面板渲染与提示）。
- 验证：40 文件 **430 项测试通过**（新增 4：菜园面板开合与直点同路、直点浇水、灶台/餐桌面板同结算、attention 契约设施状态）；`vue-tsc` 与 `vite build` 通过。
- 验收与复现步骤见 [acceptance/facility-panel-v1](acceptance/facility-panel-v1/README.md)。

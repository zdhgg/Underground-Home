# 第一层内容与跨层动力：诊断与可选方向

基线：分支 `codex/first-spring-breakthrough`，从 `1fbbe83` 出发。前四节是诊断（代码事实），阶段 1 已按本文实施，见「已实施」一节。
依据：AGENTS.md、`docs/GAME_BRIEF.md` v0.5、`docs/PHASES.md` 与现有实现。

## 结论

反馈的三条（第一层内容少 / 两层联系不大 / 挖下去没动力）在代码里是**同一个根因的三种表现**：

> 两层之间没有任何一条会流动的东西。第一层有电、有床、有 87 格可挖土，但没有任何"还需要"；第二层有水、有 54 格可挖土，但水不解决第一层的任何问题。

所以补内容有两种做法：往第一层**塞东西**（治症状），或者让第一层的空间**重新有用途**、并让下行的水**解决第一层已有的需求**（治根因）。本文推荐后者，因为它复用已有的睡眠舱 / 伙伴 / 挖掘系统，不新增子系统就能同时改善三条。

## 现状清点（真实数字，来自代码）

| | 第 1 层 · 暖窝层 | 第 2 层 · 泉水层 |
| --- | --- | --- |
| 可挖松软泥土 | **87 格**（左翼 13×3、右翼 16×3） | **54 格** + 7 格裂纹岩（唯一通路） |
| 初始已挖空 | 大厅 9×5、地表竖井、左门 | 3 处天然洞穴（8×4、7×3、5×3） |
| 可互动物件 | 能源石 ×1、能源核心 ×1 | 泉水 ×1 |
| 可放置设施 | 睡眠舱 ×1（代码硬限 1 间） | 小壁灯（纯装饰，不产不耗） |
| 任务步数 | 4 步（找石头→收石头→修核心→安床） | 5 步（听水声→换镐→挖通→下去→找到水） |
| 做完之后 | 家园静态：灯常亮、伙伴已入睡，无新需求 | 走廊 + 壁灯，无新需求 |

两个关键数字：

- **87 格可挖土，只服务一间 3×2 的床。** 地形上第一层放得下 31 个舱位（实测：挖空两翼后有 31 个合法落点），但 `src/app/session.ts:189` 用 `world.pods.length === 0` 把舱数锁死在 1 间。孩子挖出来的房间没有东西可放。
- **操作次数其实两层相当**（各约 10 次点击）。所以"内容少"不是次数问题，而是：第一层**做完就静止**，且它的**空间没有第二种用途**。

## 三个问题的机制原因

### 1. 第一层内容少
- 舱数上限 1（`session.ts:189`），伙伴固定 2 位（`friendRoutes.ts:8`）。床只建一间，剩下的土挖开只是空。
- 泥土里除了能源石没有别的东西（`world.ts` `LANDMARKS`），挖开没有任何"发现"。
- 能源核心修好之后不消耗、不分配、不产出：灯亮即结束，第一层没有任何需要玩家照看的东西。

### 2. 两层联系不大
- 唯一的跨层机制是**门票**：`exploration.ts:97` 要求 `coreRepaired && pods.length > 0` 才能发现裂纹。也就是说"上一层做完了"允许你下去，而不是"上一层需要下面"。
- **反向联系为零**：第二层找不到任何第一层用得上的东西；第一层的电对第二层没有任何作用。
- 第二层连床都不给放（`build.ts:54` 对 `y >= 15` 一律返回 `locked-layer`），唯一的自由建设是壁灯，而壁灯不产不耗。

### 3. 挖下去动力不足
- 破岩的奖励是"一片空地 + 一盏装饰灯"，不是"解决一个已经存在的问题"。
- **时机错了**：破岩发生在第一层任务全部完成之后，此时玩家所有的需求都已被满足，没有任何未满足的拉力。台词"水就在下面"对 7 岁儿童是命令，不是动机。
- 奖励在挖通前不可见：孩子看不到下面有什么值得挖。

## 三个方向

| | 做法 | 解决哪条 | 代价 |
| --- | --- | --- | --- |
| **A（推荐）** | 床数 = 伙伴数；伙伴数由"水"决定。第 3 位伙伴"有水才来住" → 需求先出现，再给下行通道 | 1、3（部分 2） | 小：复用睡眠舱/伙伴/挖掘 |
| **B** | 在 A 之上做真实双向循环：**水向上**（引水到第一层 → 解锁种植槽 → 收获 → 喂饱伙伴）、**电向下**（第一层核心的电引到第二层设施） | 1、2、3 全部 | 中：分 3 个阶段，新增水/食物计数与种植槽 |
| **C** | 让挖掘本身有发现：第一层泥土里埋几件旧避难所遗物（坏工具、种子、旧灯），挖开就有小奖励 | 1（只治症状） | 很小，但**不解决两层联系**，建议作为 A 的一部分而非独立方向 |

### 推荐方向 A 的具体形状

把现有系统接起来，不新增子系统：

1. **睡眠舱上限从 1 间放开**（地形已验证支持 31 个落点），但**不放开伙伴数量**——每间舱都要有人来住，避免空舱（这正是当初限 1 间的理由）。
2. **第 3、4 位伙伴需要"水"才肯搬进来**。这样"床的数量"变成跨层进度的函数，玩家在第二层做的事直接决定第一层还能不能继续建。
3. **需求先于通道出现**：第二位伙伴入住后，伙伴说"想种点吃的"，阿土才说"我听到下面有水"。顺序反过来的话，下行就只是任务清单的下一行。
4. 顺带**埋 2–3 件可发现物**（方向 C 的最小形态），让第一层每一格土都有期待。

预期效果：第一层从"4 步教学 + 一块空地"变成**长线居住空间**；"为什么挖下去"从台词变成玩家的处境（下不去就没有新伙伴、没有吃的）。

### 顺带修掉的一个真问题

放开第二间舱之后暴露出来：**睡眠舱可以堵死"大厅地面 → 梯口"的唯一地面通道**。原来只有"发现裂纹时"会检查这条路，一旦玩家在发现裂纹之后再建第二间舱，存档载入时的通路校验就会失败——也就是"存了却读不回来"。现在把这条通道规则提到了建造合法性里（`canPlacePod` 用 `hallToShaftRouteIntact` 预演放置结果），建造时就拦住，提示仍是孩子能读懂的"小床的门要通到家里，也要给伙伴和核心留条路"。

- 规则：`core/exploration.ts` 抽出 `hallToShaftRouteIntact`，`core/build.ts` 在放舱前用它试算（临时把候选舱放进世界再撤回），与存档校验共用同一条规则。
- 旧档安全：发现裂纹的那一刻本来就要求过这条路，所以已有存档不会因此变成非法。

### 验证结果

- `npm test`：**160 项通过**（原 145 项 + 新增 15：伙伴与床位规则、遗物发现/撤销、走廊不可截断、第二间舱的入场与存档重载、6 步引导、高亮回到暖窝层）。
- `npm run build`：`vue-tsc --noEmit` + Vite 生产构建通过。
- 位于第二层时的实机验证（内置浏览器）：载入"已找到泉水 + 1 间舱"的存档后，界面显示「安顿新朋友 5/6」、阿土说"还有 2 位朋友说：有水就搬来住"、建造工具重新出现、画面里两位新朋友站在大厅、两位老住户睡在舱里；挖开一格泥土后遗物小道具出现且左下角显示「遗物 1/3」。

### 已知问题与下一步

- 本轮验证用内置浏览器时，第二间舱的**入场演出依赖逐帧推进**，该面板的帧会被节流；动画逻辑本身已有自动测试覆盖（手动 tick 到结束），但没能在该面板里跑完整段演出。
- 遗物"已发现"由地图推导（那一格是否挖空），所以**撤销会把遗物埋回土里**，再挖开又会出现；这与"挖掘可撤销"一致，但和任务进度位的单调性不同，属于有意选择（不新增存档字段、不动存档版本）。
- 如果孩子仍然觉得第一层"空"，下一阶段（阶段 2：把水引上来 → 第一层种植槽与收获）就是补空间用途的下一步。

## 结构性约束（做规划时要先知道）

1. **目前只有两层，没有第三层。** `STRATA` 只有 home/seal/water；泉水层地板在 y=22，下面 y=23–27 只有 5 行实心岩，装不下第三层。
2. **扩图要打断旧存档。** `persistence.ts:74` 校验 `width/height` 必须等于 `MAP_WIDTH/MAP_HEIGHT`。加第三层需要同时改地图尺寸、递增 `WORLD_VERSION` 并写迁移（现有迁移只覆盖 v2/v4→v5），否则旧档直接判为不可读。
3. 第二层的 `locked-layer` 限制（`build.ts`）是刻意的——深层建设留给后续阶段。

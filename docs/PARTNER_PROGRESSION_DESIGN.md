# 伙伴、主线与能力成长

日期：2026-10-18。状态：设计决策；第8节阿土首条互动与小铁镐升级已实施，随后按[分阶段方案](ATU_HOME_IMPLEMENTATION_PLAN.md)完成阿土控制、房间基础、三位伙伴专业工作，以及阿灯的第一项照明升级。结果见[第3阶段工作验收](acceptance/partner-work-v1/README.md)、[第4阶段聚光灯罩验收](acceptance/adeng-light-v1/README.md)。小满和小泉的进一步升级仍为规划；文末首条闭环记录保留当时范围。

本决策承接本轮讨论：自由探索和自由建设为主体；阿土串联主线，其余伙伴在专业节点接力；后续允许新伙伴加入，伙伴升级帮助解决营地问题。与旧文档中“愿望持续推动任务链”的建议不一致时，以本决策和`AGENTS.md`的自由建设基线为准。

> 2026-10-20 更新：小满不再“第一间床后加入”，改为第一次下到泉水层时加入，让第一层专属于家、第二层承接水与种植。见[验收记录](acceptance/layer2-xiaoman-v1/README.md)。

## 1. 三条成长线

1. **玩家探索与建设**：决定路线、房间用途、设施位置和推进时间。
2. **阿土串起故事**：发现值得探索的问题，解释变化，连接下一处线索。同一时刻突出一个主要悬念。
3. **伙伴带来解决办法**：在照明、水、种植等专业场景发挥作用，升级扩大营地能解决的问题范围。

循环：**玩家拓展家园 → 遇到真实环境问题 → 伙伴提出办法 → 玩家选择探索、升级或另一种解法 → 新能力被实际使用 → 家园发生可见变化。**

愿望是伙伴的表达与可选建设灵感。无需先领取；提前完成的有效建设直接得到回应；不额外锁住房间布局或已经开放的挖掘。

## 2. 阿土是故事主线，其他伙伴是专业角色

| 伙伴 | 核心作用 | 出场与剧情位置 | 可以怎样成长（后续方向） |
| --- | --- | --- | --- |
| 阿土 | 探索、挖掘和串联线索 | 初始陪伴；听到水声、发现裂纹、抵达新层 | 挖软土 → 小铁镐处理裂纹岩 → 后章工具处理新的指定岩层 |
| 阿灯 | 照明、表达地下环境的情绪 | 初始躲在角落，修好核心后飞出来；新通道变亮时回应 | 小范围陪伴照明 → 照见较远洞壁的线索 → 帮助布置更大区域的照明 |
| 小满 | 种植、把探索成果变成营地生活 | **第一次下到泉水层时加入**；水到家后承接种植与吃饭 | 认识种子、一起种菜 → 照料一片菜槽 → 适应后续新生态区的作物 |
| 小泉 | 水路、连接上下两层 | 找到泉水后加入，接过关于水的讲述 | 接通现有水路 → 为扩建区域分水 → 借助后续泵站或循环设施解决更远的供水 |

后两列包含规划，不表示当前版本已有这些能力。现有阿土换铁镐、引水、种菜、送电等规则是可复用的基础。

阿土不替所有人讲话：水的问题由小泉解释，种植的变化由小满表达。其他伙伴的加入不自动增加一条常驻主线，也不同时弹出多个待办。

## 3. 升级要改变“能做什么”

优先用孩子听得懂的名字，例如“小铁镐”“远光灯”“育苗工具”，而不是只显示等级和加成。

每次升级应当有五个要素：

- 一个已经能观察到的问题：裂纹挡住通道、扩建区太暗、水路还没接过去。
- 一个明确的新办法：换工具、改进照明、增加供水分支。
- 一次有意义的探索或共同实践，让改进有来由。
- 玩家主动选择升级；条件和结果在操作前说清楚。
- 一次可见的使用结果：阿土挥镐后通道打开，或新区域获得实际照明。

不通过重复点角色、挂机经验或纯粹“挖N格”升级。不为升级引入饥饿倒计时、惩罚和必须每天照料的压力。首版不铺开多分支技能树。

**升级的目标是减轻或拓宽建设，而非制造重复劳动。** 获得供水能力之后，不为了证明升级有用而强迫玩家不断打水。

## 4. 营地问题从扩建中自然产生

| 玩家做了什么 | 新出现的问题 | 伙伴可以提供的办法 | 仍保留的自由 |
| --- | --- | --- | --- |
| 挖到岩层交界 | 特定裂纹岩阻挡通路 | 阿土换小铁镐，执行施工 | 何时推进、选择已开放的哪条路线、先在本层扩建 |
| 向侧面扩大生活空间 | 新房间离已有光源较远 | 布置壁灯，或后续改进阿灯的照明能力 | 房间位置、灯具布局、暂时先建设别处 |
| 建起新的生态区 | 现有水路尚未覆盖 | 小泉帮助接出分支水路 | 生态区位置、接管路线、建设顺序 |
| 找到新的适宜种植环境 | 现有种植办法需要适应 | 小满研究新的种植方法 | 是否经营这片区域、采用哪些已开放作物 |

现有设施继续有效；不因人口增加或剧情推进而突然断水、掉级或损坏。问题没有倒计时，孩子可随时暂停主线。

工具、地质、道路和水电等世界规则仍有效。能力不会把首章所有坚硬基岩变成可挖，也不会让伙伴隔墙施工或凭空送水。

## 5. 互动入口承接玩法

点伙伴时展示当前情境的一小段话，以及至多一个相关的主要操作：

- 点阿土：谈眼前线索；条件合适时可以查看工具改进或指向可施工区域。
- 点阿灯：谈当前光照；未来可邀请照明或查看灯具改进。
- 点小满：看看菜的情况；成熟时指向收获，有食物时承接一起吃饭。
- 点小泉：谈当前水路；已有水源时提供接管相关操作。

操作必须接入真实规则与场景结果，不能只有换一句台词。关闭对话后继续自由探索，不自动接受任务。拖地图不触发对话；建造选址期间不抢走点击；小尺寸角色提供适度点击容错。

伙伴可在固定设施点表现简单生活动作，让“在家里做什么”可见。优先使用现有的一次性路径和短演出；首版不实现自主目标规划、排班或复杂居民AI。

## 6. 新伙伴如何加入

每位新伙伴的设计先回答：

1. 在哪里、因为什么遇见？
2. 能为哪类营地或探索问题提供新办法？
3. 与已有伙伴能力有哪些区别，能否协作？
4. 加入后世界立即发生什么可见变化？
5. 后续升级能解决什么更大的问题？

例如未来的侦察型伙伴可以帮助判断洞壁后是否有空洞，工匠型伙伴可以改进设施。这里不预定人数、角色名称或加入顺序，也不把旧成长文档里的候选名单视为已批准开发范围。

每个章节只引入少量新能力；先让孩子用过一次，再介绍下一种。已有伙伴保留核心用途，不能因新人到来就完全失去作用。

## 7. 工程扩展边界

本决策前，`core/partners.ts`用人数、数组位置和连续切片推导成员；渲染配色与部分位置也按索引对应。本轮已改成稳定ID、独立加入条件和显式床位优先位，颜色与站位也按ID取值。不能把数组位置当永久身份。

后续最小结构采用稳定的`partnerId`、`abilityId`和`upgradeId`：

| 部分 | 责任 |
| --- | --- |
| 伙伴定义 | 身份、名字、物种、加入条件、专业能力引用 |
| 伙伴状态 | 已加入哪些稳定ID、实际获得哪些升级；由版本化存档保存 |
| 能力与升级规则 | 适用目标、前置条件、升级结果；纯函数，不依赖Pixi/Vue |
| 营地状态 | 地图、设施、水电、作物等真实状态；对话从中推导当前问题 |
| 主线与剧情 | 监听真实发现和变化，选择当前说话者与单一主要线索 |
| 会话层 | 组合点击、规则执行、保存和演出通知 |
| 渲染与界面 | 命中区域、对话、升级前后造型、施工与完成反馈 |

保持范围小：新伙伴通过定义接入已有能力类型，新能力类型仍需要明确实现和测试；不为未知伙伴搭建通用脚本系统或大型事件框架。

扩展约束：

- 返回明确的已加入ID列表，不再用“人数=名单前N位”代表身份；床位占用也引用ID。
- 伙伴美术和能力用ID匹配，名单重排不改已有进度、外观或床位。
- 主线检查实际世界条件或能力结果，不依赖“第几个伙伴已升到几级”。
- 同一升级状态只有一个来源。阿土已有的`pickaxeUpgraded`须被兼容复用或一次性迁移，不能与新等级字段互相矛盾。
- 涉及新持久状态时才升级存档，保留旧档既有工具和设施成果；未知ID不得转成另一位伙伴；加载失败有反馈。
- 展示未完成的规划能力，不得作为已实现能力让玩家付出资源。

## 8. 下一实施阶段：先完成一条可玩的闭环

先验证阿土，不同时制作四套升级系统：

**点阿土 → 交流已发现的裂纹/水声 → 查看小铁镐能做什么 → 沿用已有条件换工具 → 玩家选择施工目标 → 阿土沿真实通道执行 → 岩块与梯道变化 → 伙伴回应。**

- 复用当前小铁镐解锁条件及裂纹岩规则，不收回已开放的能力，不添加刷经验或材料系统。
- 同步把伙伴身份接入边界理顺，避免以后按序号追加人物。
- 其他伙伴先按营地状态给出专业回应，保留以后接入真实能力升级的位置。
- 点角色、关闭对话、拖图、挖掘和建造选址必须互不误触。
- 只有这一条验证成立后，再单独选择阿灯照明或小泉水路作为下一条能力闭环。

本阶段不同时加入新伙伴、第三层、水量模拟、泵站、工作台或完整技能树。

## 9. 验收标准

- 孩子能说出“阿土的新工具解决了什么”，并亲自选一次目标使用。
- 不点击伙伴或搁置其建议，仍能在已开放区域自由建设。
- 已经换过铁镐的存档不会重复升级、失去工具或再次付费。
- 新加入一位伙伴时，现有四位的身份、美术、床位和进度保持一致。
- 同一时刻只突出一个主要线索，专业伙伴在相应节点自己表达。
- 升级有真实规则结果和可见场景反馈；失败操作不消耗、不越过岩层或道路限制。

## 10. 首条闭环实施记录（2026-10-18）

已实现第8节范围：点击场景伙伴或面板上的“和阿土聊聊”，查看当前线索及小铁镐能力；听过裂纹处水声后可以换镐，显示“已装备”，实际选择裂纹才开始走位和施工。升级后阿土平时也拿着镐，挖开一块有一句短回应。其余三位可按现有光照、供水、种植状态回应，未提供未实现的升级按钮。

数据层新增`partnerAbilities.ts`与`partnerInteractions.ts`，身份、加入条件、床位按稳定ID匹配；未知ID不会回退成阿土。当前仍从既有世界状态推导成员、使用原`pickaxeUpgraded`字段和原存档版本，没有新增等级、经验或持续愿望字段。新伙伴的持久加入状态与自由分配床位留给实际需要时再做版本化迁移。

角色点击有屏幕像素容错；实心土/岩仍交给挖掘和施工；拖图、建造选址、全景观察与交流入口区分。详细验证、复现、变更文件和未完成项见 [伙伴互动首版验收](acceptance/partner-interaction-v1/README.md)。

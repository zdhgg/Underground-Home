## 0. 先看结论

### 0.1 一句话

**《地下小家园》是一个“为朋友建造地下家园”的游戏。**

你是一群小动物里最会挖洞的那一个。地表刮着风暴，大家躲进一座又黑又冷的旧避难所。玩家通过挖掘、建造、连接设施和邀请伙伴，把岩洞一层一层变成温暖、能运转的家。

挖是手段，建是手段，探索是手段。**“朋友们还需要什么”才是目的。**

## 1. 游戏定位

### 1.1 一句话定位

面向 7 岁儿童、兼顾 6—10 岁的 **2D 横截面地下家园建造与探索游戏**。玩家在旧避难所里自由挖掘、建造设施、接通水电、邀请伙伴，把一张连续的岩层剖面逐渐变成多层地下家园。

### 1.2 玩家幻想

> “我是这群小动物里最会挖洞、最会造家的那一个。朋友说冷，我就挖出暖和的房间；朋友说饿，我就引水种菜；朋友说想住得近一点，我就再往下挖一层。”

玩家不是“操作一台挖掘机”，也不是“管理一座工厂”。玩家是**被朋友需要的建设者**。

### 1.3 目标玩家与体验目标

| 项目 | 设计口径 |
| --- | --- |
| 核心玩家 | 7 岁儿童；6—10 岁可玩 |
| 阅读能力 | 不依赖大量识字；短句、图标、语音式口吻；关键操作有图形反馈 |
| 单次游玩 | 10—20 分钟可以完成一件小事；一层约 30—60 分钟（估算，需试玩校准） |
| 完整流程 | 地表序章 + 9 层；时长待逐层试玩校准，不以层数推算承诺时长 |
| 主要设备 | 桌面浏览器、平板横屏；鼠标或单指触控 |
| 操作前提 | 单击、拖动、点按大按钮；不要求双指、长按、精确计时或键盘 |
| 陪伴方式 | 可独立玩；家长可在旁边读短句、一起看全景 |

**7 岁玩家能独立完成的最低标准：**

- 看得懂“现在要做什么”，不需要读完整段说明。
- 点一个目标，伙伴自己走过去执行，不需要先手动站位。
- 建造前能看到预览、能不能建、建完会变成什么样。
- 点错了能撤销；施工到一半能停；刷新后主要成果还在。
- 找不到伙伴或楼层时，有一个大按钮能把自己带回熟悉的地方。

### 1.4 情绪基调

**温暖、安全、探索、被需要。**

- 光：从黑暗到一盏灯、一层灯、四层通明。
- 水：从听见滴水，到水接到菜园，到第一顿饭。
- 食物：从一颗种子，到收成，到大家围在一起吃。
- 朋友：从躲在世界各地，到各有床位、各有工作、最后住进同一个家。
- 探索：不是“前面有危险”，而是“下面好像还有东西”。

不制造恐惧、失败感、时间压力，也不把“照顾”变成打卡。

### 1.5 不是什么

| 不是 | 原因 |
| --- | --- |
| 不是挖矿游戏 | 挖矿经济会把核心动词从“照顾”变成“刷资源” |
| 不是战斗游戏 | 当前开发线不加入敌对生物、武器、伤害和死亡 |
| 不是生存游戏 | 没有饥饿条、口渴条、体温条、倒计时和失败重开 |
| 不是经济或经营模拟 | 不做货币、交易、稀有度、抽卡、装备数值 |
| 不是随机沙盒 | 固定手工蓝图，保证 7 岁孩子不迷路、任务引导可靠 |
| 不是独立楼层关卡 | 始终是一张连续剖面，不做切层加载和独立小地图 |
| 不是复杂居民 AI | 伙伴只做“玩家指定目标 → 走过去 → 一次性演出”，不做自主排程和关系模拟 |

### 1.6 当前版本的位置

v0.2.0 已经能玩到：

- 一张 44×28 的连续剖面，地表、暖窝层、坚硬岩层、泉水层在同一张图里。
- 第一层：找能源石、修核心、点灯、建两人小窝、旧物收藏、客厅。
- 突破岩层：听水声、换小铁镐、逐段破岩、接木梯、下到第二层。
- 第二层：找到泉水、把水接到菜园、种菜收菜、第一顿饭、壁灯、聚光灯罩。
- 跨层连接：把电从第一层送到第二层；水电都真实影响画面和设施。
- 伙伴：阿土、阿灯、小满、小泉，各有外形、出场时刻、专业工作和简短对话。
- 建设：预设洞室一键开工，阿土逐格挖土并完成设施；挖土掉落石料／旧木料；可停工、可撤销。
- 存档：v13，自动保存、继续游戏、旧档迁移、加载失败反馈。
- 美术：手绘地形、角色、核心、能源石、梯架、灯具、小窝、客厅、雪面与风暴；单张素材失败时回退程序化造型。

**v0.2.0 还没有：** 第三、四层，厨房与共餐设施，工坊与材料加工，电梯与竖向交通，阿岩与阿木，更多能力升级，完整的 15 项发现图鉴，公共家园与中期庆典。本文以下内容会逐项标明状态。

## 2. 设计不变量

这十条是后续所有内容的“宪法”。任何新功能如果违反其中一条，应先修改设计，而不是先写代码。

1. **家是主语。** 挖、建、探索、连接都是为了让家变好；不能回答“家发生了什么变化”的内容不加。
2. **自由建设是主体。** 任务给方向和理由，不规定唯一房间位置、唯一挖掘路线或唯一设施摆法。
3. **玩家指定目标，伙伴执行。** 不做多角色切换栏，不做复杂编队；点目标，伙伴沿真实通路走过去完成。
4. **一次只教一件事。** 新动词先被用一次，再介绍下一个；同一节点不同时解锁两个系统。
5. **每个动作都有即时、可见的反馈。** 尘土、材料、灯光、水位、作物、伙伴表情、里程碑卡片，至少有一种。
6. **没有失败惩罚。** 不死亡、不饥饿、不倒塌、不损坏已建设施、不因离线或倒计时失去成果。
7. **环境问题是章节谜题，不是生存压力。** 可预见、可逆、可暂停、可忽略；解决后一定带来可见的家园变化。
8. **一张连续剖面。** 楼层是同一张图上的命名横带，不是独立地图；镜头可以跳层，世界始终连续。
9. **误操作可撤销，施工可中断。** 撤销保护伙伴、通路和已建设施；中断不重复结算、不锁死输入。
10. **存档版本化，失败有反馈。** 不静默丢档，不用重开游戏代替迁移，不上传用户信息与密钥。

## 3. 核心循环

### 3.1 五拍循环

```
朋友说出一件家里缺的事，或环境露出一个线索
        ↓
玩家判断“这需要什么”：空间？材料？水？电？还是一个人？
        ↓
玩家指定一个目标：挖一格、开一间洞室、接一段水、装一盏灯
        ↓
伙伴沿真实通路走过去，动手，世界发生改变
        ↓
家变亮 / 变暖 / 多一张床 / 多一顿饭 / 多一条路
        ↓
朋友回应，出现下一个问题或下一处发现
```

五个拍点：**问题 → 目标 → 执行 → 变化 → 回应。**

当前版本中，这条循环的实例：

- 阿土说“这里好黑” → 玩家挖能源石 → 修核心 → 灯一盏盏亮 → 阿灯从角落飞出来。
- 小满在泉水层喊饿 → 玩家破岩、下梯 → 找到泉水 → 小泉接水 → 菜园种菜 → 第一顿饭。
- 第二层还是黑的 → 玩家点“把电送到下面” → 阿土沿梯道铺线 → 壁灯亮起 → 阿灯可以加装灯罩。

### 3.2 四个时间尺度

| 尺度 | 玩家在做什么 | 当前版本 | 完整版目标 |
| --- | --- | --- | --- |
| 30 秒 | 点一个目标，看伙伴动手，得到反馈 | ✅ 挖一格、尘土、材料、短句 | 保持；任何新设施都必须有 30 秒内可感知的反馈 |
| 5 分钟 | 解决一件家里的小事 | ✅ 修核心、建小窝、接水、收一茬菜 | 每层持续提供“5 分钟能完成”的小目标 |
| 30—60 分钟 | 让这一层变一个样 | ◐ 第 1、2 层已有主线，但第 2 层生活闭环未满 | 每层一个完整章节：到达 → 解决 3—5 个问题 → 点亮／住人／产出 → 章末庆祝 |
| 全程 | 从地表走到第 9 层 | ◐ 只有前两层 | 序章 + 9 层 + 终章；每层结尾都能回看整个家 |

> 时间数字是设计估算，不是对儿童的硬性时长要求。孩子可以在一层待很久，也可以很快推进；没有倒计时。

### 3.3 三条循环

**空间循环：**

```
挖出空间 → 放下设施 → 伙伴使用 → 家变热闹 → 需要更多空间
```

**连接循环：**

```
下面有水 → 水引上来 → 菜园有产出 → 伙伴愿意住 → 需要更多电和空间
上面有电 → 电送下去 → 下面亮起来 → 能建更多设施 → 需要更多材料
下面有材料 → 材料运上来 → 工作台加工 → 更好的设施 → 能挖得更深
```

**情感循环：**

```
朋友提出需要 → 玩家为他做一件事 → 朋友回应 → 玩家感到“被需要”
→ 朋友提出下一个需要（但不是无限清单）
```

三条循环必须同时存在。只有空间循环会变成“摆家具”；只有连接循环会变成“接水管模拟器”；只有情感循环会变成“接任务—交任务”。

### 3.4 完成态：完成是下一章的开始

每一层都要有一个**明确的完成态**，避免“永远有新愿望 = 永远做不完”。

| 层 | 完成态 |
| --- | --- |
| 第 1 层 | 灯全亮，两位伙伴有床，旧物有地方摆，第一次向下突破成功 |
| 第 2 层 | 水接到菜园，灶台和餐桌可用，大家围坐吃完第一顿饭，第二层亮起来；水塔／育苗不阻塞完成态 |
| 第 3 层 | 电梯连通三层，工坊能加工材料，晶簇层亮起来 |
| 第 4 层 | 六位伙伴都有住处，公共大厅建成，关键里程碑完成，暖屋宴到齐；不要求 15 项发现全部收集 |

> 第 2 层的“第一顿饭”当前已有按钮演出；阶段 2A 在保留现有按钮兼容入口的同时，增加灶台／餐桌的实体场景。第 4 层暖屋宴只要求关键里程碑与公共家园完成；未发现项可以留白，终章后仍可继续探索。

完成态之后，玩家仍可自由建设、收藏、改造布局。**“完成”不是内容耗尽，而是下一章的开始。**

### 3.5 循环不该长成的样子

- 点一下没有可见变化，只增加一个数字。
- 当前目标是一张越来越长的清单，而不是一个具体的朋友或问题。
- 玩家为了“证明系统有用”反复打水、反复送电、反复刷材料。
- 孩子离开几分钟，回来发现家坏了、作物枯了、伙伴饿了。
- 任务要求把房间放在唯一正确的位置。

出现以上任何一种，优先删内容或改规则，而不是加更多内容。

## 4. 六类核心玩法

| 玩法 | 一句话 | 当前状态 | 完整版重点 |
| --- | --- | --- | --- |
| 挖掘探索 | 点开泥土、岩层和隐藏空间 | ✅ 单格挖土、裂纹岩、梯道、泉水 | 硬岩、晶簇洞、深层线索；不做“挖 N 格” |
| 自由建设 | 在已开放区域决定空间与设施 | ✅ 预设洞室、自由挖土、菜槽、壁灯 | 更多设施、扩建、公共空间；不锁布局 |
| 设施连接 | 让水、电、材料和人上下流动 | ✅ 水上行、电下行、梯道 | 水塔、配电、电梯、工坊；不做微观管线 |
| 伙伴协作 | 点目标，让对应伙伴去完成 | ✅ 4 位伙伴、3 类专业工作、一次一项 | 6 位伙伴、6 条能力线、通勤与生活演出 |
| 发现收藏 | 挖到旧物、地质和故事 | ✅ 3 件旧物、收藏架、物品栏故事 | 15 项发现、家园相册、旧住户故事 |
| 家园生活 | 睡觉、吃饭、休息、庆祝 | ✅ 入舱睡眠、第一顿饭、客厅、里程碑 | 厨房、实体共餐、公共大厅、终章生活 |

### 4.1 挖掘探索

**玩家在做什么：** 点泥土或裂纹岩，指定“我要这里变成空间”；阿土沿真实通路走过去，落爪／落镐后才改变地形。

**当前实现：**

- 松软泥土一格一格挖；坚硬岩石暂不可挖；带裂纹的岩脉用小铁镐逐段破开。
- 裂纹岩是“施工委托”：阿土走到真实施工点，落镐那一刻才破开并接长木梯。
- 前两段各点一次学会指挥，第三段起可以“一路挖到底”。
- 挖土掉落石料或旧木料，进入顶部物品栏；失败、空地、硬岩不掉落。
- 误挖可在本次会话内撤销；撤销保护伙伴站位、通路和设施。

**规划：**

- 第 3 层加入晶簇洞、硬岩盖层和更明确的地质线索；阿岩加入后，他的“凿”让指定硬岩变成可施工目标。
- 用声音、湿痕、微光、岩层颜色提前预告“下面有什么”，让玩家因为好奇而挖，而不是因为任务要求。
- 深层探索仍然是一张连续剖面，不做独立地牢。

**边界：**

- 不做“挖 N 格土”主线。
- 不做随机矿脉、矿石价格、背包负重。
- 不做挖掘伤害、塌方埋人、工具耐久。

### 4.2 自由建设

**玩家在做什么：** 决定“这里放什么、家往哪边扩”；可以点预设洞室直接开工，也可以在已开放区域自由挖土、摆设施。

**当前实现：**

- 第一层：两人小窝、暖暖客厅、新朋友的小窝；第二层：泉边小菜园、泉边小洞室（种菜或休息二选一）。
- 预设洞室显示用途、费用和“开工”；阿土沿真实通路逐格清土并自动完成设施。
- 第二层右侧仍有自由挖土和摆菜槽的空间。
- 建造预览有绿／红轮廓；可取消、可停工、可撤销；完工才扣材料。
- 房间可扩建，扩建要包住原房间、保持用途；旧设施和未完成蓝图保留。

**规划：**

- 更多“同构设施”复用同一套占地、承托、连通、通路规则：睡眠舱、储物架、灶台、水塔、工作台、电梯、深层灯等。
- 结构扩建：住处加宽、第三间小窝、电梯井、公共大厅。
- 功能改造：加装灯罩、接分支水路、加配电箱、客厅改共餐区。
- 生活升级：床品、灯色、旧物角、壁画、纪念墙；不影响数值，不强制。

**边界：**

- 不做固定房型拼图，不要求房间必须正方形或唯一位置。
- 不做复杂承重、氧气、通风、温度模拟。
- 不做“拆错就损失材料”的惩罚；撤销退材料，施工中断保留已挖空间。

### 4.3 设施连接

**玩家在做什么：** 把“下面的水”接到“上面的菜园”，把“上面的电”送到“下面的灯”，把“下面的材料”送到“上面的工坊”，让人能上下班。

**当前实现：**

- 水：找到泉水 → 小泉接水管 → 水缸和水管出现在大厅／梯道旁 → 菜园解锁。
- 电：核心修好 → 点“把电送到下面” → 阿土沿梯道铺线 → 第二层壁灯真正亮起。
- 人：木梯是唯一上下通道；伙伴沿真实通路走到设施旁工作。
- 光：壁灯只照已挖通的空间，遇土／岩截断；聚光灯罩把左右各 2 格扩大到各 4 格。

**规划：**

- 第 3 层：晶簇采集 → 配电箱 → 电梯／深层灯；水塔／水泵把水稳定送到多处设施和上层；工作台把材料变成设施部件。
- 连接必须是“看得见的”：发光线、流动的水、上下移动的吊篮、伙伴的通勤路线。
- 连接可以很慷慨：水只作为连接状态与可视水流，不设水量消耗；电力不足只让非关键灯变暗或电梯等待，不损坏设施。
- 后期可自动化：小水车、配电优先级等只作为可选增强，不成为维持家园的必需；不做补水跑腿。

**边界：**

- 不做复杂管网编辑、流量数值、压力计算、断电惩罚。
- 不做“每天打水／每天加油”的重复劳动。
- 不因为连接失败而让已建成的家失效。

### 4.4 伙伴协作

**玩家在做什么：** 点一个设施或目标，对应的伙伴自己走过去完成；玩家不需要先选人，也不需要管理排班。

**当前实现：**

- 四位伙伴：阿土（挖）、阿灯（照）、小满（种）、小泉（引）。
- 阿灯一开始躲在角落，修好核心后飞出来；小满第一次下到泉水层才出现；小泉找到泉水后从水里冒出来。
- 专业工作：小满收菜、小泉接水管、阿灯装壁灯／加装灯罩；一次一项，有操作者、查看和停止入口。
- 伙伴保留床位，在设施／公共区域旁待命；“伙伴在哪”只定位镜头，不切换控制。
- 伙伴走真实通路，不穿墙、不隔空工作；走不到会说原因。

**规划：**

- 第 3 层加入阿岩（凿）和阿木（造）；六位伙伴各有一条能力线。
- 伙伴可以乘电梯上下、去工坊／菜园／公共大厅工作，晚上回床；仍用“一次性演出参数化”，不做持续 AI。
- 每位伙伴在自己的专业节点说话；同一时刻只突出一个主要线索，不弹出多个待办。
- 伙伴的加入条件与能力升级用稳定 ID 保存，不按名单序号推断身份。

**边界：**

- 不做自主目标规划、排班、关系值、好感度、聊天树。
- 不做多人同时工作队列；首版仍是一项工作。
- 不因为伙伴没到场而让已建设施失效。

### 4.5 发现收藏

**玩家在做什么：** 挖到旧物、地质奇观或旧住户留下的东西，收进物品栏／收藏架，读一小段故事。

**当前实现：**

- 3 件旧物：干种子、旧扳手、旧灯罩，埋在第一层泥土里；挖开那一格才会露出。
- 物品栏显示材料与旧物；旧物有故事文本和“找找这件旧物”；大厅有收藏架，点亮后可展示。
- 能源石和泉水是主线关键发现，也构成“这个世界有东西可找”的基础。
- 旧物不进任务链，玩家可以完全无视；撤销会把旧物埋回土里，再挖开再次发现。

**规划：**

- 全版本 15 项发现，分布在四层：旧物、矿物、生物、遗迹、地质奇观。
- 每项发现都要有：藏在哪里、怎么露出、看到什么反馈、图鉴里记什么、给世界什么暗示。
- 第 4 层把收藏变成“家园相册／纪念墙”：不是数值奖励，而是玩家自己讲“这是我们家第一次亮灯的时候”。
- 关键发现可以给升级线索，但不做“集齐 10 个换奖励”的清单。

**边界：**

- 不做抽卡、稀有度、掉落概率、重复刷取。
- 不做纯收集清单；每项发现至少带来一句故事、一个画面或一个线索。
- 不用发现物当货币。

### 4.6 家园生活

**玩家在做什么：** 让伙伴住下来、睡好、吃饭、休息、一起庆祝；最后把家变成大家愿意待的地方。

**当前实现：**

- 睡眠舱建成后伙伴沿真实通道入舱，钻进被窝，呼吸起伏；刷新后直接恢复睡眠。
- 菜成熟后小满收菜，食物 +1；点“请大家吃饭”消耗一份食物，播放开心蹦跳和彩纸。
- 暖暖客厅有座椅和茶桌；伙伴可在设施旁待命。
- 里程碑卡片：第一次破岩、第一次下到第二层、发现泉水、第一份收成等。

**规划：**

- 第 2 层：灶台／小厨房、餐桌／共餐区，把“吃饭按钮”变成空间里的生活。
- 第 4 层：公共大厅／长桌、纪念墙／家园相册、观景窗；六位伙伴一起过“暖屋日”。
- 生活升级是自愿的：更好的床品、灯色、座椅、壁画；没有舒适度数值，不强制。
- 食物是共享生活的道具，不是饥饿条；没有食物只会少一次庆祝，不会失败、掉属性或死亡。

**边界：**

- 不做饥饿、口渴、体力、心情、清洁度等持续需求条。
- 不做每日任务、在线奖励、连续登录。
- 不做复杂居民 AI 或生活模拟；生活以短演出和可见陈设为主。

## 5. 九层内容规划

### 5.0 总览

| 章节 | 名称 | 主题 | 家里的新问题 | 新动词 | 新伙伴 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |
| 序章 | 风暴地表 | 离开与进入 | 风暴来了，住哪里 | 走、看、进入 | 阿土（序章）；阿灯在第 1 层登场 | 演出 ✅；可玩序章 ◐ |
| 第 1 层 | 暖窝层 | 居住 | 黑、冷、没有地方睡 | 挖、修、建、照 | 阿土、阿灯 | ✅ 基础闭环 |
| 第 2 层 | 泉水层 | 生产 | 没水、没吃的、新朋友在等床 | 引、种、收、煮 | 小满、小泉 | 核心 ✅；生活闭环 ◐ |
| 第 3 层 | 晶簇层 | 能源、工坊、垂直交通 | 家变大了，电不够，上下太难 | 凿、接、造、乘 | 阿岩、阿木 | ◐ |
| 第 4 层 | 公共家园层 | 公共生活与中期庆典 | 各有房间，却没有共同的客厅 | 聚、宴、纪念、回望 | 无新增；六人同住 | ◐ |

> 层深是设计尺度，不是当前代码坐标。当前代码只有暖窝层和泉水层；第三、四层需要扩图与存档迁移，详见第 11.8 节。

### 5.1 地表序章

**状态：** 进入页、雪景、风暴和约 16 秒开场演出已实现；可玩的序章交互为 ◐。

**作用：**

- 交代“为什么住到地下”：地表风暴、旧避难所、朋友们又冷又怕。
- 教会最基本的操作：看、点、走近、进入。
- 建立情绪：从风雪里进入一个更暗但更安全的地方。
- 不在这里做地表自由建造、地表基地、战斗或资源采集。

**规划形状（5—8 分钟以内）：**

1. 雪地进入页：继续游戏／开始游戏／更新记录（已实现）。
2. 阿土喊冷、发现入口、带大家进入竖井（已实现的演出）。
3. 1—2 个轻交互：帮朋友捡一件旧物、选择一件带进地下的纪念品、推开避难所的门。
4. 进入大厅，看到停转的能源核心，接第 1 层主线。

**边界：**

- 地表不是可自由探索的第二张地图；序章结束就进入地下。
- 不做地表天气伤害、冻死、物资搜索。
- 是否把序章扩展为可自由走动，需在儿童试玩后决定；当前只确定“短、轻、不抢主线”。

### 5.2 第 1 层 · 暖窝层

**状态：** ✅ 基础玩法与定位已实现。

**主题：** 居住。把又黑又冷的旧避难所变成“今晚能睡”的家。

**家里的新问题：**

- 这里好黑，我有点怕。
- 亮了，可是我们睡哪儿？
- 旧避难所里好像还有以前住户留下的东西。

**玩家新动词：** 挖 ✅、修 ✅、建 ✅、照 ✅。

**关键设施：**

- 能源核心（固定）：全家的总电源。
- 睡眠舱／两人小窝（预设 + 可建）：床位与入住。
- 暖暖客厅（预设）：座椅、茶桌、日常休息与伙伴待命；是家里的休息角，不承担六人聚会或终章。
- 壁灯／顶灯（固定 + 可建）：局部照明。
- 储物架（◐）：材料与旧物收纳，让库存可见。

**发现物：**

- 能源石（✅ 主线）。
- 干种子、旧扳手、旧灯罩（✅ 3 件旧物）。
- 旧照片、旧钥匙（◐，为旧住户故事和第四层埋线索）。

**伙伴：** 阿土、阿灯。

**章末完成态：** 灯全亮；两位伙伴有床；旧物有地方摆；第一次听到楼下水声，决定往下挖。

**本层明确不做：**

- 不做厨房、工坊、电梯、晶簇、公共大厅。
- 不提前塞入第 2—4 层的生产系统。
- 不因为“第一层是教学层”就把它做成一次性关卡；它永远是总部的电、床、客厅和储物所在。

**设计要点：**

- 第一层是“家的心脏”，不是“第一关”。后面的层越深，越需要第一层的电、住处和公共空间。
- 预设洞室降低 7 岁儿童的空间规划负担，但右侧软土和自由摆放仍保留；玩家可以自己决定家往哪边扩。
- 旧物收藏是第一层的“发现课”：教孩子“挖土不只为了空间，也可能挖到故事”。

### 5.3 第 2 层 · 泉水层

**状态：** 核心闭环 ✅；完整生活闭环 ◐。

**主题：** 生产。让家有水、有菜、有第一顿饭。

**家里的新问题：**

- 没水，没法做饭。
- 小满在楼下喊饿；新朋友要有水才肯住。
- 菜长出来了，可是没有地方做熟、没有地方一起吃。

**玩家新动词：** 引 ✅、种 ✅、收 ✅、煮 ◐（当前是“请大家吃饭”按钮，灶台待做）。

**关键设施：**

- 泉水／取水点（✅ 固定）。
- 水缸 + 水管（✅ 随引水出现）。
- 种植槽（✅ 可建 + 预设菜园）。
- 灶台／小厨房（◐，优先）：把收成做熟，让第一顿饭有实体场景；优先用现有石料与旧木料，红黏土不作为前置。
- 餐桌／共餐区（◐，优先）：大家围坐吃饭，伙伴给出回应。
- 水塔／水泵（◐，按需）：多处设施或上层需要稳定供水时才引入。
- 育苗架／小温室（◐，按需）：现有菜种单一或菜苗不稳时才引入。

**发现物：**

- 地下泉水（✅ 主线）。
- 发光蘑菇、红黏土、水纹石（◐）。

**伙伴：** 小满（第一次下到泉水层加入）、小泉（找到泉水后加入）。

**章末完成态：** 水接到菜园；灶台和餐桌可用；大家围坐吃完第一顿饭；第二层壁灯亮起；电从第一层送下来。水塔／育苗不阻塞完成态。

**优先生活闭环：** 种菜 → 收菜 → 灶台做熟 → 端上餐桌 → 伙伴围坐 → 一句回应。当前版本已有种菜、收菜和“请大家吃饭”按钮演出；阶段 2A 保留当前按钮作为简化入口，并增加可见的灶台／餐桌场景。水塔、育苗是后续补强，不是这条闭环的前置；红黏土不作为 2A 前置。

**本层明确不做：**

- 不做饥饿条；食物只用于共餐和庆祝，不逼迫玩家持续种菜。
- 不做真实时间等待；作物按玩家行动推进，孩子随时可以收。
- 不做复杂烹饪配方树；灶台先做“把菜做熟、一起吃”的最小闭环。
- 不把水做成需要频繁打水的跑腿；当前不引入水量消耗、补水跑腿或复杂资源数值。
- 水塔／育苗只有在试玩暴露独立问题后才实施；不为了证明系统有用而加入额外压力。

**设计要点：**

- 第二层是“生产层”，但不是“工厂”。它要让孩子感到“我种出了大家吃的东西”，而不是“我在管理产量”。
- 水从下面上来、电从上面下去、人在上下之间走，这三条流让第 1、2 层互相需要。
- 第一顿饭是情绪高潮，不是数值奖励；吃完之后，家才真的像家。

### 5.4 第 3 层 · 晶簇层

**状态：** ◐ 已确定，尚未实现。

**主题：** 能源、工坊、垂直交通。家变大了，需要更多电、更好的工具、更深的探索。

**家里的新问题：**

- 灯越来越多，第一层的电不够用了。
- 上下三层靠爬梯太慢，伙伴和材料都运不过来。
- 硬岩挡住了更深处；普通铁镐挖不动。
- 下面的晶簇会发光，也会让灯一闪一闪。

**玩家新动词：** 凿 ◐、接 ◐、造 ◐、乘 ◐。

**关键设施：**

- 晶簇采集台（◐）：采集晶簇，作为新能源。
- 配电箱（◐）：把电分到各层，优先保证灯和电梯。
- 工作台／工坊（◐）：把材料加工成设施部件。
- 电梯井／吊篮（◐）：贯通多层，既是交通也是镜头跳层入口。
- 熔炉／材料加工（◐）：把矿石、晶簇变成建材。
- 深层灯（◐）：照亮晶簇层，光不穿硬岩。

**发现物：**

- 晶簇、晶苔、旧钻头（◐）。

**伙伴：**

- 阿岩（穿山甲，凿）：玩家先在第二层边缘的硬岩裂隙旁听见他；用现有挖土、裂纹岩和梯道到达他所在的侧洞。阿岩加入后，硬岩爪成为可用能力；玩家主动选择可达面，才凿开硬岩盖层，打开第三层入口。
- 阿木（松鼠，造）：第三层工作台框架建成后加入。

**章末完成态：** 电梯连通第 1—3 层；工坊能加工材料；晶簇层亮起来；硬岩不再是无解的墙，而是可选择的施工目标。

**本层明确不做：**

- 不做战斗、怪物、Boss；晶簇是能源和发现物，不是敌人。
- 不做复杂电路模拟、断电惩罚、电缆颜色谜题。
- 不做“挖矿经济”；晶簇只用于建造和升级，不换钱、不交易。
- 不做独立矿洞地图；晶簇层仍是连续剖面的一条带。

**设计要点：**

- 第三层是“能力升级层”：玩家第一次感到“我的手变强了”，能凿硬岩、能造更大的东西、能坐电梯上下。
- 阿岩负责“开层与结构”：从可达面凿开硬岩盖层、开新层、支撑大空间；阿土的硬岩镐负责“定点破岩”：在已打开区域处理小块硬岩、矿脉和挡路岩块，不负责开新层。两者不互相替代。
- 阿岩的加入发生在凿开主盖层之前：玩家先用现有能力接近他，再加入，最后才凿开盖层。不要写成“打通盖层后才出现”。
- 阿岩和阿木分别解决“开层”和“造物”；两人不要同时登场，中间至少隔一个主要建造目标。
- 垂直交通是第三层的核心体验：伙伴真的会乘电梯上下，材料真的会被运上来。

### 5.5 第 4 层 · 暖光大厅

**当前主题：** 中途暖屋与公共生活。六位伙伴需要一个共同相聚的地方；最终结局留在第九层。

**完整流程：** 三层电梯首次回家 → 到旧梯口检查木梁 → 主动安装支撑 → 阿岩逐段凿开盖层 → 真实沿梯进入 → 电梯延长第四站 → 接通暖光 → 自由选择八格宽、四格高的公共大厅位置 → 组装六人长桌 → 自由挂纪念墙 → 补齐六个床位 → 邀请六人沿真实通路到场 → 消耗一份收成，暖屋宴完成。

**自由建设：** 大厅、纪念墙与岩壁双人小窝均由玩家选址；小窝复用真实床位，不是装饰计数。前三层床位照常有效。预设洞穴只是起始空间，不是固定布局。大厅使用已有材料与工坊部件，不增加新资源链。

**发现与纪念：** 旧壁画、旧灯芯可选发现，不阻塞进度。纪念墙只记录实际完成的点灯、找水、第一次共餐、工坊、四层电梯与暖屋宴；未发生的经历不编造。旧钥匙仅为故事线索，不是进入本层的必需品。

**风险：** 阿岩先说明木梁松动，玩家再决定加固。未加固只暂停新梯道开工，随时可退出、回家、挖土或加工；不坍塌、不伤害、不计时、不损坏旧设施。

**章末：** 全员有床，大厅、长桌、暖光、电梯、纪念墙建好，六位伙伴确实到场后才记录完成；演出中取消不扣食物。完成后继续自由建设，可翻相册、再聚餐、查看四层全景。没有“全游戏结束”或第五层伪入口。

**第四层当时边界：** 观景天窗、独立“大件组装”技能树、随机灾害、新资源链不实施。第五层的最新授权与新伙伴扩展见 [LAYER5_SCOPE.md](LAYER5_SCOPE.md)。

| 能力 | 阿岩·凿 | 阿土·硬岩镐 |
| --- | --- | --- |
| 主要用途 | 开硬岩盖层、开新层、支撑大空间 | 在已打开区域定点处理小块硬岩、矿脉和挡路岩块 |

**能力线原则：**

- 每条能力线至少有一个“孩子能说出来的新做法”，而不是“效率 +10%”。
- 升级名称用孩子听得懂的工具名：小铁镐、聚光灯罩、育苗工具、分水阀、硬岩爪、稳定支撑、精密工具、大件组装。
- 升级状态只有“未解锁／可学习／已装备／已学会”这类明确状态，不显示等级、经验、星级。
- 同一能力只有一个状态来源；旧字段能复用就复用，不制造两个互相矛盾的等级。

| 6 | 硬岩镐 | 阿土／挖 | 第 3 层 | 进入第三层后，小块硬岩、矿脉或挡路岩块挡路 | 定点处理小块硬岩、矿脉和挡路岩块；不负责开新层 | 阿岩已打开第三层 + 工坊／晶簇 | ◐ |
| 7 | 远光灯 | 阿灯／照 | 第 3 层 | 晶簇层太大，普通灯照不远 | 更远照明，照出晶簇反光 | 晶簇层 + 深层灯 | ◐ |
| 8 | 稳定支撑 | 阿岩／凿 | 第 3—4 层 | 大空间和电梯井施工不安全 | 支撑大洞室、竖井和电梯井 | 硬岩爪 + 工坊 | ◐ |
| 9 | 精密工具 | 阿木／造 | 第 3 层 | 工作台只能做简单部件 | 制作高级设施和精密部件 | 工作台建成 | ◐ |
| 10 | 大件组装 | 阿木／造 | 第 4 层 | 公共大厅、长桌、电梯轿厢太大 | 把部件组装成大件设施 | 精密工具 + 公共层 | ◐ |

**升级验收标准：**

- 孩子能说出“这个新工具解决了什么”，并亲自选一次目标使用。
- 升级前后同一空间有可见差异；已有灯、水、床、菜不退化。
- 升级是玩家主动选择，条件和结果在操作前说清楚；不反复扣费，不重复升级。
- 不因为升级而打开未发现的地层；不把首章所有硬岩一次性变成可挖。
- 刷新后能力保留；旧档不会因为新增升级字段而失去已有成果。

### 6.4 加入节奏与协作原则

**加入节奏：**

| 阶段 | 新伙伴 | 加入时刻 | 之前的铺垫 |
| --- | --- | --- | --- |
| 第 1 层 | 阿土、阿灯 | 初始；阿灯修核心后正式出现 | 阿灯躲在角落，只有尾灯微光 |
| 第 2 层 | 小满 | 第一次下到泉水层 | 楼下传来“我饿了”的声音 |
| 第 2 层 | 小泉 | 找到泉水 | 泉水露面，小泉从水里冒出来 |
| 第二层边缘 → 第三层入口 | 阿岩 | 先接近，后加入：第二层边缘硬岩裂隙旁有抓挠声；玩家用现有能力到达侧洞后加入；加入后才凿开主盖层 | 硬岩里有抓挠声、碎屑掉落；侧洞可达 |
| 第 3 层 | 阿木 | 工作台框架建成 | 工具声、木屑、旧工具箱 |

- 阿岩的加入顺序固定为“先用现有能力接近 → 阿岩加入 → 再凿开主盖层”。不要把“打通盖层”写成阿岩的加入条件。
- 每层最多引入 2 位新伙伴，且必须由两个不同的主要目标隔开；不允许同一次演出加入两位。
- 第 4 层不新增伙伴，让六个人一起完成公共家园。
- 新伙伴加入时，世界必须立刻发生可见变化：多一张床、多一盏灯、多一条路、多一个工作点。

**协作原则：**

- 玩家不选人：点设施／目标，系统自动分配对应伙伴。
- 一次只做一项专业工作；有操作者、查看和停止入口。
- 伙伴走真实通路，不穿墙、不瞬移、不隔空工作；走不到就说原因。
- 同一时刻只突出一个主要线索；其他伙伴在自己的专业节点说话，不抢主线。
- 伙伴可以有自己的小动作、待机、睡眠、吃饭，但不做自主目标规划、排班和关系模拟。

### 6.5 明确不做的伙伴系统

- 第五层已增加第七位伙伴苔苔；独立探测型伙伴与宠物系统仍不在本次范围。
- 不做好感度、关系值、礼物、恋爱、结婚、生育。
- 不做对话树、分支剧情、角色个人结局。
- 不做自主寻路 AI、排班、日程、需求条、工作队列。
- 不做多人联机、角色交易、角色抽卡。
- 不把伙伴做成“必须按顺序招募，否则卡关”：主线关键伙伴（如阿岩）可以打开新层，但接近条件必须用已有能力可达，加入后立刻获得对应能力；其他伙伴的能力是拓宽，不是唯一钥匙。

## 7. 建筑与升级规划

### 7.1 三种升级方式

建筑升级采用 **结构扩建、功能改造、生活升级** 三种方式，不采用复杂数值等级。

| 方式 | 玩家看到的变化 | 例子 | 规则 | 当前 |
| --- | --- | --- | --- | --- |
| 结构扩建 | 空间更大、多一层、多一条通道 | 住处加宽、第三间小窝、电梯井、公共大厅 | 必须包住原结构、保持用途、有承托、不堵唯一通路；撤销退材料 | 部分 ✅（住处扩建已有入口）；第三间小窝、电梯井、公共大厅 ◐ |
| 功能改造 | 同一空间多一种用途 | 加装灯罩、接分支水路、加配电箱、加储物架 | 保留原设施，不重复扣费，状态可见，可撤销 | ✅ 灯罩；水路、配电、储物 ◐ |
| 生活升级 | 更好看、更舒服、有回忆 | 床品、灯色、旧物角、壁画、纪念墙 | 不影响数值、不强制、不锁进度；纯自愿 | ◐ |

**不采用：**

- 不做 Lv.1—Lv.5、星级、品质、稀有度。
- 不做设施耐久、损坏、维修、离线衰减。
- 不做“升级失败降级”“材料损失”“必须每天维护”。
- 不做复杂技能树；能力线是并列的，不是互相排斥的天赋树。

- 如果后续需要收缩，优先删“纯装饰、无连接”的设施，不删水、电、交通、工坊等连接性设施。

### 7.3 放置与撤销规则

**所有可建设施共用一套孩子能理解的规则：**

1. **有承托：** 设施下面要有实心地面，不能悬空。
2. **有通路：** 设施的门或使用点要连到已挖通的家园；不能堵住唯一通道。
3. **不重叠：** 不压住能源核心、泉水、梯道、其他设施和伙伴站位。
4. **有预览：** 放置前显示占地、绿／红轮廓和一句原因；点“确认”才落位。
5. **可撤销：** 本次会话内可撤回建造和挖掘；撤销退材料，保护伙伴、通路和已建设施。
6. **可中断：** 施工到一半可以停；已挖空间和掉落保留；重新开工从剩余部分继续。
7. **不惩罚：** 位置不合法只解释原因，不扣材料、不损坏已有设施。

**未来扩展：**

- 设施从“一个睡眠舱一个校验函数”扩展为“设施表 + 通用校验器”；睡眠舱、储物架、灶台、水塔、工作台、电梯、深层灯共用占地、承托、连通、通路四条规则。
- 新设施必须声明：占地、使用点、可见状态、连接对象、撤销行为、存档字段。
- 不要求玩家手动旋转、微调像素或对齐网格；默认横平竖直，减少触控精度负担。

### 7.4 材料与成本

| 材料 | 来源 | 用途 | 状态 |
| --- | --- | --- | --- |
| 石料 | 挖松软泥土 | 住处、客厅、菜园、基础设施 | ✅ |
| 旧木料 | 挖松软泥土（部分格） | 床、座椅、菜槽、门框 | ✅ |
| 红黏土 | 第 2 层泉边 | 陶罐、后续装饰、育苗架改进；不作为 2A 灶台／餐桌的必要材料 | ◐ |
| 发光蘑菇 | 第 2 层潮湿洞壁 | 柔和光源、装饰、灯 | ◐ |
| 晶簇 | 第 3 层硬岩 | 能源、深层灯、工坊 | ◐ |
| 矿石 | 第 3 层硬岩 | 工具、电梯、熔炉 | ◐ |

**材料规则：**

- 全版本最多 6 种建造材料；不做货币、交易、拍卖、稀有度。
- 成本保持“一小把”：一间住处、一个菜园、一盏灯，通常是几次挖掘就能凑齐的量。
- 挖土有产出，但产出是建造条件，不是刷取目标；不做“挖 100 格解锁”。
- 缺材料时提示“去挖附近的泥土找材料”，不嘲讽、不惩罚、不扣已有材料。
- 开工时检查材料，完工才扣费；不提前扣款，不重复扣款；撤销退材料。
- 食物、水、电不是材料：食物用于共餐，水／电是连接状态；都不做成需要反复补满的数值条。
- 红黏土在 2C 才发现，只用于后续装饰或设施改进；2A 的灶台／餐桌优先使用现有石料与旧木料，不等待红黏土。

### 7.5 设施连接网络

| 网络 | 流向 | 当前 | 规划 | 孩子能看到的证据 |
| --- | --- | --- | --- | --- |
| 电 | 上 → 下 | ✅ 核心 → 梯道 → 第二层壁灯 | 配电箱 → 第 3、4 层灯／电梯 | 发光电线、灯亮、电梯动 |
| 水 | 下 → 上 | ✅ 泉水 → 水管 → 水缸 → 菜园 | 水塔／水泵 → 灶台／育苗架，并为上层供水 | 水流、水缸可视水位、菜苗 |
| 材料 | 下 → 上 | ◐ 当前石料／旧木料在挖掘地直接入包，没有专门的跨层运输 | 黏土、蘑菇、晶簇、矿石 → 工坊／电梯运上来 | 掉落、背包、工坊加工 |
| 人 | 双向 | ✅ 梯道；伙伴走到设施旁 | 电梯／吊篮；伙伴通勤 | 伙伴上下楼、进设施 |
| 食物 | 第 2 层 → 公共区 | ✅ 收成、第一顿饭（当前为按钮演出） | 灶台 → 餐桌 → 公共大厅 | 菜、锅、餐桌、伙伴围坐 |
| 光 | 上 → 下／局部 | ✅ 壁灯、灯罩 | 深层灯、远光灯 | 光圈、黑暗退去、晶簇反光 |

**连接设计原则：**

- 每条连接至少有一个“看得见的证据”：线、水、光、移动的人或材料。
- 连接失败只让相关设施暂停或变暗，不损坏、不倒扣、不连锁失败。
- 连接不需要玩家理解真实物理；用“水往低处流、电沿梯道走、人坐电梯”这种孩子能复述的规则。
- 连接的价值是“让上下互相需要”，不是“让玩家每天维护”。

### 7.6 不做的建筑系统

- 不做复杂承重、结构力学、坍塌模拟。
- 不做流体／气体模拟、管道压力、电路逻辑门。
- 不做设施耐久、维修、离线损坏。
- 不做自由旋转、像素级装饰、大型家具目录。
- 不做“建筑等级 + 属性加成”的数值系统。
- 不做独立楼层地图、切层加载、每层单独存档。

## 8. 自然环境问题

### 8.1 原则

自然环境是**章节问题的来源**，不是生存压力。

1. **可预见：** 问题出现前有声音、颜色、湿痕、微光、伙伴提醒。
2. **可逆：** 玩家可以修、可以绕、可以暂时不管；不会永久失去东西。
3. **无惩罚：** 不死亡、不饥饿、不掉属性、不损坏已建设施、不倒计时。
4. **可暂停：** 孩子可以停下来自由建设，问题不会恶化。
5. **有回报：** 解决问题后，家一定发生可见变化：多一条路、多一层光、多一个空间、多一个朋友。

### 8.2 章节问题

| 章节 | 自然现象 | 玩家先看到／听到什么 | 玩家可以做什么 | 结果 | 不做什么 |
| --- | --- | --- | --- | --- | --- |
| 地表序章 | 风暴、雪 | 风声、雪、阿土喊冷 | 进入避难所 | 到达安全的大厅 | 不做冻伤、天气伤害、倒计时 |
| 第 1 层 | 黑暗、寒气 | 昏暗大厅、角落里的阿灯、竖井冷风 | 找能源石、修核心、点灯、建床 | 灯亮、家暖、伙伴入住 | 不做体温条、感冒、夜间袭击 |
| 第 2 层 | 潮气、渗水 | 水滴声、湿痕、裂纹冒水汽 | 听水声、破岩、找泉、接水 | 水到菜园、菜长出来、第一顿饭 | 不做洪水、淹死、作物枯死 |
| 第 3 层 | 晶簇脉冲、硬岩 | 灯一闪一闪、岩壁里有抓挠声、晶簇反光 | 找阿岩、凿硬岩、装配电箱、建电梯 | 电稳了、硬岩通了、电梯动了 | 不做爆炸、断电惩罚、怪物 |
| 第 3—4 层 | 落石、沉降 | 头顶掉小石子、路面出现裂缝、伙伴提醒 | 阿岩支撑、清理碎石、改道 | 新空间稳定、通道打开 | 不做塌方埋人、设施摧毁 |
| 第 4 层 | 旧梁松动与回声 | 轻轻吱呀、伙伴提醒、旧门纹路 | 建公共大厅、办暖屋日、看全景 | 四层通明、中期庆典 | 不做最终战斗、逃生倒计时 |

### 8.3 表现与反馈

- **先画面，后规则：** 先用声音、粒子、颜色变化告诉玩家“这里有问题”，再用一句短句说明能做什么。
- **问题有名字：** 孩子能说“灯在闪”“上面掉土”“水从缝里出来”，而不是“系统异常”。
- **解决有演出：** 水通、电通、灯亮、门开、伙伴回应；至少一个镜头变化。
- **失败没有惩罚：** 如果玩家暂时不处理，问题保持原样；不恶化、不扣资源、不锁主线。
- **一次只处理一个问题：** 同一时刻只有一个主要环境问题，不叠加三个警报。

### 8.4 不做的灾害

- 不做火灾、洪水、地震、疾病、辐射、毒气。
- 不做会摧毁已建设施的灾害。
- 不做需要每日处理的维护事件。
- 不做“天气影响产量／心情／健康”的数值系统。
- 不做随机灾害；所有章节问题都是手工设计、可预期、可复现的。

## 9. 操作与界面原则

### 9.1 输入模型

| 玩家意图 | 输入 | 结果 | 当前 |
| --- | --- | --- | --- |
| 挖土／指定施工 | 点松软泥土 | 选中一格，阿土走近，落爪后挖开 | ✅ |
| 处理裂纹岩 | 点裂纹岩 | 阿土走近听水声／挥镐；满足条件后逐段破岩 | ✅ |
| 走到某处 | 点已挖空的地面 | 阿土沿真实通路走过去；这是当前实际行为 | ✅ |
| 平移地图 | 按住拖动 | 只移动镜头，不挖土、不移动阿土 | ✅ |
| 缩放 | 点 +／- 按钮 | 放大／缩小；当前不支持双指捏合 | ✅ |
| 建造 | 点洞室／设施卡片 → 看预览 → 开工／确认 | 显示占地、费用、合法性；阿土逐格施工 | ✅ |
| 取消／撤销 | 点取消／撤销 | 退出当前选址或撤回本次操作 | ✅ |
| 找伙伴 | 点“伙伴在哪” | 只移动镜头，不切换控制 | ✅ |
| 看楼层 | 点“回到家园／向下看看／全景” | 镜头跳转，不改变世界 | ✅ |
| 看收藏 | 点物品栏／收藏架 | 打开物品栏，查看材料、旧物和故事 | ✅ |

**空地点击的事实口径：** 当前 `src/app/session.ts` 在点击格为 `TILE.EMPTY` 时调用 `atuOrders.request(cell, 'move')`；`src/app/atuOrders.ts` 使用 `moveDestination` 让阿土沿真实通路走过去，`tests/session-exploration.test.ts` 也覆盖“空地可移动”。README 中“点击已经挖空的空地不再移动阿土”是历史描述，与当前代码／测试不一致；本文以实际代码行为为准。本次只记录差异，不修改 README，也不改变输入逻辑。

**原则：**

- 一种输入只做一件事；点击和拖动互不误触。
- 不要求双击、长按、双指、精确拖拽或键盘。
- 点错不惩罚；能撤销、能停、能改目标。
- 小角色有适度点击容错；设施和按钮的触控面积不小于 44px。
- 一次只允许一个主要行动；施工、工作、演出期间收紧输入，但不锁死取消入口。

### 9.2 建造与撤销

**建造流程：**

```
点洞室／设施卡片
  → 看用途、费用、会变成什么样
  → 点“开工”
  → 阿土沿真实通路逐格清土
  → 自动完成设施
  → 材料在完工时扣除
```

**建造反馈：**

- 绿色轮廓：可以建；红色轮廓：不可以，附一句孩子能读懂的原因。
- 预览显示占地、门／使用点、是否挡住通路。
- 施工中可以停；已挖空间和掉落保留；重新开工从剩余部分继续。
- 完成后有里程碑卡片、镜头变化或伙伴回应。
- 撤销退材料，保留已挖空间；保护伙伴、通路和已建设施。

**不允许：**

- 不合法位置扣材料。
- 施工中断后按钮永久卡住。
- 刷新后重复扣费或重复完成。
- 撤销把伙伴埋进土里或切断唯一通路。

### 9.3 镜头与楼层导航

- **一张连续剖面：** 镜头平移、缩放、跳层都在同一张图上。
- **最多三个跳转目标：** 回家、当前层、下一层；不做自由选层列表。
- **深度尺：** 显示层名、深度和“你在这里”；孩子对“往下多少米”的直觉强于编号。
- **家园标记：** 已建成区域在地图边缘有常驻标记，避免迷路。
- **目标高亮：** 只高亮当前一个目标；不把整层都点亮。
- **镜头不抢操作：** 阿土自己行动时镜头跟随（跨层走位把镜头带过去）；玩家在同一趟里拖图或缩放，镜头立即让位到该趟结束，下一趟行动再恢复。伙伴工作与“找到伙伴”不拉走镜头。
- **全景：** 只用于观察和庆祝，不在全景里挖掘；点“回到家园”回到可操作状态。

### 9.4 HUD 与信息层级

从上到下、从少到多：

1. **当前目标卡：** 一句话标题 + 一句“现在做什么” + 一句“做完会怎样”。
2. **资源条：** 石料、旧木料；后续材料最多 6 种，超过时收进物品栏。
3. **主要行动按钮：** 当前最该做的一件事；不同时出现多个同等重要的按钮。
4. **伙伴入口：** “伙伴在哪”；不常驻显示所有人。
5. **收藏／物品栏：** 材料、旧物、故事。
6. **楼层／深度：** 当前层名、深度尺、最多三个跳转目标。
7. **图例／提示：** 短句、图标；不堆术语。

**信息原则：**

- 一次只突出一个主要目标；其他信息可折叠。
- 数字只用于库存和计数，不用于“攻击力／效率／等级”。
- 图标优先于文字；文字优先于表格。
- 重要状态用“画面”表达：灯亮、水流、菜熟、伙伴在等。
- 不显示孩子无法行动的信息；不制造“系统在报警”的感觉。

### 9.5 文字与反馈

**文字规则（沿用 `CHARACTERS.md`）：**

- 一行不超过 12 个汉字；超过就拆句。
- 说“我”，不说“系统”：说“我饿了”，不说“食物值不足”。
- 每句有一个具体动作或画面：说“再挖一格”，不说“继续挖掘”。
- 一次只问一个问题；一次只给一个主要操作。
- 不用专业术语：不说“照明范围不足”，说“这里好黑，我陪你”。

**反馈规则：**

- 30 秒内必须有一次可见反馈：尘土、材料、灯光、音效、伙伴表情。
- 5 分钟内必须有一次“家变了一个样”：多一盏灯、多一张床、多一条路、多一棵菜。
- 里程碑用卡片 + 镜头 + 轻量音效；不弹长文本。
- 成功不嘲讽失败；失败提示只解释原因和下一步。
- 音效可关闭；不用突然的大音量或闪烁。

### 9.6 存档与失败反馈

- 存档使用带版本号的数据结构；当前 v13。
- 自动保存；进入页可“继续游戏”，显示上次玩到哪、第几步、保存时间。
- 旧档迁移保留地图、设施、材料、伙伴、菜园、水电、工具和探索成果。
- 读取失败时明确说明原因，禁止本次会话覆盖失败数据；不白屏、不假装保存成功。
- “重新开始”需要二次确认；清档前说清楚会失去什么。
- 不保存半段动画、工作队列或临时演出；刷新后从安全状态恢复。
- 不上传用户信息与密钥；不做账号和后端。

### 9.7 触控与可访问性

- 单指完成全部核心操作；不要求双指捏合（当前限制，后续可评估）。
- 按钮最小 44px；角色点击有额外容错。
- 颜色 + 形状 + 图标共同表达状态，不只靠颜色。
- 文字对比度足够；不把关键信息放在低对比度背景上。
- 不用快速闪烁、强震动、突然巨响。
- 提供“慢一点”的节奏：演出可跳过，提示可停留，施工可暂停。
- 目标平板上的真实触控和长时间性能仍需验收；不能只用桌面鼠标测试代替。

## 10. 内容扩展规则

### 10.1 新内容准入清单

任何新设施、新伙伴、新发现、新系统，先回答这 8 个问题：

1. **它给玩家什么新做法？** 如果只是“更多”“更快”“更强”，不是新动词，降级为装饰或不做。
2. **它服务哪一层的主题？** 不能归入任何一层主题的内容，不进主线。
3. **它连接了哪个已有系统？** 水、电、材料、人、光、食物、收藏，至少接一个。
4. **30 秒内玩家能感知到什么？** 说不出来，就加反馈或不做。
5. **5 分钟内家发生了什么变化？** 说不出来，就只是数值，不是内容。
6. **哪位伙伴会回应？** 没有伙伴回应的内容，至少要有环境反馈。
7. **怎么撤销、怎么存档、怎么加载？** 没有答案，不进入实施。
8. **它是否制造压力、倒计时、重复劳动或失败惩罚？** 是，就拒绝或改设计。

### 10.2 内容配额

| 项目 | 全版本上限 | 每个实施批次上限 | 说明 |
| --- | --- | --- | --- |
| 地下层 | 9 层 + 序章 | 1 层 | 不跳层开发；一层可分 2—3 个批次 |
| 伙伴 | 建议总计 9—10 位，逐层评审 | 每层 0—1 位为优先 | 同层最多 2 位，且分开登场；必须带来独特动词 |
| 能力线 | 6 条 | 1—2 条 | 每条至少 1 项升级 |
| 主要升级 | 10 项 | 1—2 项 | 不铺技能树 |
| 核心设施 | 20 类 | 1—3 类 | 一层可分多个批次 |
| 发现物 | 15 项 | 1—3 项 | 每项都有故事或线索 |
| 新公共系统 | 0 个 | 0 个 | 不新增货币、战斗、AI、联机 |

**配额原则：**

- 先做连接性内容（水、电、交通、工坊），再做装饰性内容。
- 一层内容做满之前，不跳到下一层；每层必须有完成态。
- 新系统必须复用已有规则；不能为单一设施造一套新引擎。
- 内容上限用于防止“功能堆砌”；如果试玩发现内容不足，优先加深已有系统，而不是突破上限。

### 10.3 命名与表达

- 用“功能 + 孩子听得懂的比喻”：小铁镐、聚光灯罩、育苗工具、分水阀、硬岩爪、稳定支撑、精密工具、大件组装。
- 不用“Lv.3 采矿效率 +15%”“稀有度 SSR”“属性词条”。
- 层名用“功能 + 名字”：暖窝层、泉水层、晶簇层、公共家园层；可附“约 -4 米”的深度。
- 设施名说“它是什么、用来做什么”：灶台、餐桌、水塔、配电箱、工作台、电梯井。
- 发现物名说“孩子看到的东西”：干种子、旧扳手、旧灯罩、发光蘑菇、红黏土、水纹石、晶簇、晶苔、旧钻头、家园壁画、地心暖光。

### 10.4 连接优先

新增内容按以下优先级排序：

1. **连接：** 让上下层互相需要的水、电、材料、人、食物。
2. **新动词：** 让玩家会做一件以前不会做的事。
3. **新空间：** 让家变大、变深、变亮。
4. **新发现：** 让世界有故事、有好奇。
5. **装饰：** 让家更好看、更像自己的。

如果预算只够做一项，做连接；如果连接已经完整，再做新动词；装饰永远最后。

### 10.5 完成态与旧文档

- 每层必须有完成态；完成态之后可以继续自由建设，但不制造“永远做不完”的清单。
- 每层结尾要有一个“回望”镜头：看自己把什么变成了家。
- 旧文档保留为历史与细节来源；本文与旧文档冲突时，以本文 v1 为总体口径。
- 任何旧提案要进入实施，先按本文的准入清单和配额重新评审，不因为“文档里写过”就自动开发。

### 10.6 看起来像内容、其实不是内容的东西

| 看起来像 | 为什么不是 | 替代做法 |
| --- | --- | --- |
| 挖 N 格土 | 只有数量，没有家的变化 | 挖出空间 → 放下设施 → 伙伴使用 |
| 收集 10 个同款材料 | 纯刷取，没有新做法 | 少量材料 + 一个新设施／新发现 |
| 每日任务 | 把照顾变成打卡 | 可选愿望、一次性发现、自由建设 |
| 设施等级 | 只有数值，没有新动词 | 结构扩建、功能改造、生活升级 |
| 更大的地图但没有新内容 | 只是走得更远 | 新层必须有新问题、新动词、新伙伴 |
| 更多伙伴但没有专业作用 | 只是收集品 | 每位伙伴一条能力线、一个工作场景 |
| 更复杂的管线 | 变成维护工作 | 一条可见的水／电主线，自动、宽容 |
| 更难的灾害 | 变成生存压力 | 可预见、可逆、无惩罚的章节谜题 |

| 批次 | 先解决的问题 | 内容 | 验收 |
| --- | --- | --- | --- |
| 2A 做饭与围坐（优先） | 菜能收，但生活场景仍像按钮 | 灶台／小厨房、餐桌／共餐区；优先复用现有石料与旧木料；保留“请大家吃饭”按钮作为简化／兼容入口；新增灶台／餐桌实体场景；伙伴围坐与回应（一次性演出，不做自主 AI）；入口共用同一结算，不重复扣食物 | 孩子能完成“种菜→做饭→大家围坐→伙伴回应”；没有饥饿条；不要求先建水塔／育苗；红黏土不作为前置 |
| 2B 水系统补强（按需） | 多处设施或上层需要稳定供水 | 水塔／水泵、分水阀；发现水纹石；只做连接与可视水流，不引入水量消耗、补水跑腿或复杂数值 | 水能稳定送到多处；旧菜园不退化；供水未接通只暂停／提示，不损坏设施 |
| 2C 育苗（按需） | 现有菜种单一、菜苗不稳 | 育苗架／小温室、育苗工具；发现发光蘑菇、红黏土；生长仍按玩家行动推进 | 能种新作物；不做真实等待；旧菜园和收成不变 |
| 2D 生活补全 | 旧物和材料没有可见收纳 | 储物架（第一层补全）；发现旧照片、旧钥匙 | 旧物有地方摆；旧住户故事可回看；不阻塞 2A |

**2A 材料原则：** 灶台／餐桌优先使用现有石料与旧木料，红黏土不作为 2A 前置。红黏土在 2C 才发现，只用于后续装饰或设施改进，不阻塞 2A 生活闭环。

**发现物配额：** 2B—2D 的 5 项发现（水纹石、发光蘑菇、红黏土、旧照片、旧钥匙）是规划目标，不是第二层基本体验完成、进入第三层的硬性条件。2B—2D 未完成时，2A 仍可成立；不新增第 16 项发现。

**现有吃饭功能兼容：**

- 复用现有食物与共餐逻辑：`src/core/farm.ts` 的 `feedPartners()` 每次消耗 1 份食物；`src/app/session.ts` 已有吃饭演出；`src/App.vue` 已有“请大家吃饭”按钮。2A 不另造烹饪经济系统。
- 保留旧按钮作为简化和兼容入口；建成灶台、餐桌后，新增伙伴前往餐桌、围坐吃饭和回应的实体场景。
- 多种入口复用同一结算流程，不能重复扣除食物。
- 未建设新设施的旧存档仍可使用原吃饭方式。
- 当前存档没有独立的“首次共餐完成”标记；2A 若需要持久记录章末完成态，必须先定义兼容旧档的迁移方案，不能凭空认定旧档完成，也不能强迫旧玩家重做既有进度。

**阶段 2 验收：**

- 2A 完成后，孩子能说出“小满种菜、我们一起做饭吃饭”，并能指出灶台／餐桌。
- 水、电、菜、饭在同一层发生；2B／2C 未完成时，2A 的生活闭环仍成立。
- 没有饥饿条；不种菜也能继续玩，只是少一次共餐。
- 旧档的水、菜、伙伴、床位、电全部保留。
- 2A—2D 各自可独立回退；不把多个批次混在一个提交里。

**实施与试玩：**

- 2A 开始后同步做小范围儿童试玩与交互观察，不等全部批次完成。
- 2B／2C／2D 实施前，必须在对应批次说明“它解决的独立问题”；如果试玩没有暴露该问题，可以暂缓，不为了证明系统有用而加入水量消耗或育苗压力。
- 水塔／水泵／分水阀／育苗保留在规划中，但不是 2A 的前置，也不阻塞第二层基本体验。

**工程注意：**

- 新增设施沿用现有占地、承托、连通、通路规则；不写新的巨型引擎。
- 新增存档字段要版本化；旧档迁移保留已有成果。
- 不修改地图尺寸；第三层扩图留到第二层基本体验稳定后的 3.0 试点。

### 11.4 阶段 3：第三层晶簇层

**目标：** 让玩家第一次感到“我能挖得更深、造得更大、上下更方便”。

**建议拆成 4 个子阶段，每阶段可独立验收；3.0 只在第二层基本体验稳定后启动：**

| 子阶段 | 内容 | 验收 |
| --- | --- | --- |
| 3.0 纵深试点 | 只改蓝图数据：加高剖面、加硬岩盖层、把晶簇层位置留出来；规则、任务、渲染尽量不动 | 给孩子看 10 秒，能回答“这个家有几层”；老玩家不读教程仍能走完前两层 |
| 3.1 接近阿岩与硬岩盖层 | 第二层边缘侧洞、硬岩裂隙线索、阿岩加入；加入后用硬岩爪凿开主盖层 | 玩家先用现有挖土／裂纹岩／梯道到达侧洞；阿岩加入前主盖层不可挖；加入后才打开通道；硬岩爪不用于精细矿脉 |
| 3.2 晶簇与能源 | 晶簇采集台、配电箱、深层灯、远光灯 | 电分到第三层；灯亮；晶簇不是货币 |
| 3.3 工坊与阿木 | 工作台、熔炉、阿木加入、精密工具、硬岩镐 | 材料能加工成设施部件；阿土的硬岩镐能定点处理小块硬岩／矿脉，不负责开新层；旧设施不退化 |
| 3.4 垂直交通 | 电梯井／吊篮、伙伴乘梯、镜头跳层、稳定支撑 | 伙伴真实上下楼；电梯是导航入口；不穿墙、不瞬移 |

**验收：**

- 玩家能在第三层自由挖土、摆放设施、撤销、存档。
- 电梯连通第 1—3 层；伙伴能乘梯去工作、回床。
- 硬岩不是“全部开放”：阿岩只开指定盖层，阿土只处理已打开区域的小块硬岩。
- 第三层有自己的完成态：灯亮、工坊运转、电梯可用。

**工程注意：**

- 当前地图 44×28，泉水层下方只有 5 行实心岩，放不下第三层；必须扩图。
- 扩图会改变 `MAP_WIDTH`／`MAP_HEIGHT`，旧存档的尺寸校验会失效；需要递增 `WORLD_VERSION` 并写迁移。
- 放大地图后，全图 BFS、伙伴寻路、瓦片渲染会成为性能瓶颈；需要连通分量预计算、A*、视口裁剪或区块化。
- 第二层基本体验稳定后，先做 3.0 蓝图试点，验证“孩子是否真的看见层”，再投入系统改造。

### 11.5 阶段 4：第四层暖光大厅与中期暖屋宴

范围与顺序见 5.5 和 [LAYER4_SCOPE.md](LAYER4_SCOPE.md)。验收包括：加固前不能开工；真实逐段凿岩；两处旧梯口均可接入；四格高自由扩挖；自由摆放三类设施；四站电梯实际往返；六个真实床位；六位独立角色走到不同座位后才扣一份收成；相册来自已完成状态；单一主要关注对象；取消、切后台、旧回调与旧档迁移。

自动化通过不代替实景。镜头、颜色、角色遮挡、短屏滚动、六人到场观感、音量必须独立检查。第九层才承担最终回望与终章，不因第四章暖屋宴完成而宣告全游戏结束。

### 11.6 九层全部完成后的最终验收（实施批次另定）

**目标：** 把“能玩”变成“7 岁孩子能独立玩、愿意继续玩”，并完成发布前的完整回归。

**范围：**

- 汇总分阶段儿童试玩结论；补充尚未覆盖的 7 岁现场试玩与交互观察。
- 平板横屏触控：点击命中率、拖动、按钮大小、长时间性能。
- 性能：地图放大后的帧率、精灵裁剪、寻路缓存、首次加载体积。
- 音频：轻量、可关闭、不惊吓；关键反馈有声音。
- 可访问性：对比度、颜色 + 形状、减少闪烁、文字长度。
- 美术一致性：新设施与手绘风格统一；单张素材失败有回退。
- 旧档迁移回归：v13 及后续版本的存档往返、错误反馈、不覆盖失败数据。
- 发布：版本号、更新记录、发布说明、冒烟验收。

**验收：**

- 孩子能在不读教程的情况下完成第一层基础循环。
- 孩子能说出“小满来了我们能种菜”“下面的灯是家里的电送下去的”。
- 孩子会主动想继续扩建，而不是做完任务就停。
- 没有阻断性 bug、没有控制台 error、没有资源加载失败。

### 11.7 每阶段验收门

每个阶段结束都必须满足：

1. **可运行：** `npm run dev` 能启动，`npm run build` 通过，`npm test` 通过。
2. **可回退：** 有明确的 Git 提交或回退点；不把多个阶段混在一个提交里。
3. **可存档：** 新字段版本化；旧档迁移保留已有成果；加载失败有反馈。
4. **可解释：** 孩子能说出这一阶段“家里多了什么”“我会了什么新做法”。
5. **无惩罚：** 没有死亡、饥饿、倒计时、设施损坏、离线惩罚。
6. **有验收记录：** 变更文件、复现步骤、测试结果、截图、已知问题。
7. **不越界：** 不提前加入下一阶段的系统；不因为“顺手”扩大范围。
8. **有阶段试玩：** 每个可玩批次结束做一次小范围儿童试玩或交互观察；阶段 5 汇总，不把全部验证堆到最后。

### 11.8 技术约束与风险

| 风险 | 事实 | 应对 |
| --- | --- | --- |
| 地图放不下第三层 | 当前 44×28，泉水层地板 y22，下面只有 5 行实心岩 | 第二层基本体验稳定后，阶段 3.0 先扩图；世界尺寸入档，递增版本，写迁移 |

| 美术成本 | 新层、新设施、新伙伴都要手绘 | 复用风格与模块化道具；先做灰盒验证玩法，再产美术 |
| 触控与性能未验收 | 尚未完成 7 岁现场试玩和目标平板验收 | 从第二层收口起持续做小范围试玩；阶段 5 做完整验收；不以桌面鼠标测试代替 |
| 预设建造削弱自由 | 预设洞室降低门槛，但可能让玩家只会点“开工” | 保留自由挖土区和自由摆放；预设只是入口，不是唯一方式 |
| 水／食物变成跑腿 | 一旦引入水量消耗或饥饿，就会变成重复劳动 | 当前不做消耗；水只做连接与可视水流，食物只用于共餐；未来若引入，必须先证明独立问题 |

### 11.9 当前顺序与下一步

1. **先收口第二层（阶段 2）**：优先 2A“种菜 → 做饭 → 围坐 → 伙伴回应”，让实体生活场景成立；2B／2C／2D 尚未批准立即实施，按独立问题与试玩结果逐个决定。
2. **第二层收口期间同步做儿童试玩与交互验证**：不等全部批次完成，先观察孩子是否能完成做饭／围坐、是否理解灶台和餐桌、是否仍能自由建设。
3. **第二层基本体验稳定后，再启动第三层 3.0 扩图试点**：只改蓝图数据，验证孩子是否能看见“层”；不先投入硬岩、晶簇、工坊和电梯系统。
4. **之后继续分阶段儿童试玩**：每完成一个可玩的批次就做一次小范围观察，把问题收在当前层，不把全部验证堆到最后。
5. **最后做完整收尾验收（阶段 5）**：性能、触控、音频、可访问性、美术一致性、旧档迁移与发布冒烟。

> 第二层未稳定前，不启动第三层扩图试点；第三层试点也不等于第三层系统开发。

## 13. 待验证与待拍板

以下问题不阻塞本文档成立，但会影响后续实施细节。按优先级排列：

1. **地表序章的规模：** 保持 16 秒演出 + 1—2 个轻交互，还是扩展成 5—8 分钟可自由走动的序章？建议先保持轻量，试玩后再决定。
2. **第二层是否设床位：** 当前床位集中在第一层。六位伙伴需要第三间小窝；是扩建第一层，还是在第二层设“守夜小窝”？建议优先第一层扩建，保持“家”的集中感。
3. **水／食物容量：** 第六层已独立加入三格蓄水和花园照料额度，仅通过主动行动消耗，不改变第二层原水源，不做全家饮水惩罚。以下为最初提案的历史判断： 当前水是布尔状态、食物是计数。当前不引入水量消耗、补水跑腿或复杂资源数值；先只做水塔／水缸的连接与可视水流。若试玩证明“多处供水”需要更清楚的容量反馈，再单独评估可视水位，仍不做断水惩罚；食物只用于共餐，不做饥饿。
4. **阿岩、阿木的名字与形象：** 本文沿用旧文档的规划名；实施前可以改。已锁定的是顺序：先接近阿岩 → 阿岩加入 → 凿开主盖层；阿岩负责开层／结构，阿土的硬岩镐只做定点破岩。
5. **第三层地图尺寸：** 需要扩到多高、多宽？建议先做 3.0 蓝图试点，用孩子能否看见“层”来决定，不先写死数字。
6. **电梯的导航方式：** 第六层已采用折叠详情中的六站辅助按钮，同一时刻只推进当前目标；以下为历史建议： 电梯是设施 + 镜头跳层入口；是否需要额外的“楼层选择”UI？建议最多 3 个目标，不做自由选层列表。
7. **收藏的呈现：** 家园相册是第四层的实体纪念墙，还是随时可打开的 UI？建议两者都有：实体墙在公共大厅，UI 可随时查看。无论哪种，都不要求 15 项发现全部收集；未发现项留白，终章后继续探索。
8. **目标设备：** 桌面 + 平板横屏为主；是否必须支持竖屏手机？当前不做竖屏专属布局，若未来要上手机，优先用“电梯吸附镜头”，不切独立地图。
9. **2A 首次共餐的持久记录：** 当前存档没有独立的“首次共餐完成”标记。2A 若需要记录章末完成态，必须先定义旧档迁移和默认值；不能把未记录直接当成未完成，也不能强迫旧玩家重做。

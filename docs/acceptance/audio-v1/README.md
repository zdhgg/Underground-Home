# 关键音效与统一静音 · 第一批验收

后续背景音乐与轻环境声已在[第二批验收](../audio-v2/README.md)中补齐；本文保留第一批实施时的范围与结果。

范围：只补当前两层已有操作的声音反馈与统一开关。背景音乐、环境循环和真人配音属于后续阶段。

## 实现

- 普通挖土：真实落爪、规则成功后播放闷响与土粒声，轻微变化音高。
- 建造：预设洞室、兼容房间完工、睡眠舱、种植槽、壁灯与灯罩成功后播放短庆祝；蓝图和开工不播放完工声。
- 能源石：收集成功时发出晶体提示；安装动画确认入槽后依次播放卡扣、启动与和弦，随后阿灯出现才播放问候。
- 新伙伴：阿灯、小满使用不同的问候音；小泉沿用泉水发现的水花与短旋律，避免同一现场叠两段庆祝。
- 第二层通电：跟随现有送电演出的上行滑音与落定音。
- 撤销成功播放回收音；硬岩等挖掘失败、建造校验失败、无法撤销等入口给轻提示。
- 泉水发现庆祝只在首次抵达时播放；已经发现后重复点击水边不再重播。

全部使用本地 Web Audio 合成，不新增素材、依赖或网络请求。`gameAudio.ts` 管理共享上下文、统一输出、短时重复抑制、最多 16 个瞬时音源和庆祝优先级。开场风声也经过同一输出。开场跳过停止风声和尾音，保留上下文供正常游戏使用。

声音在开始、继续或声音按钮的用户手势中解锁；未解锁、暂停、静音、后台期间的事件直接丢弃，不排队补播。切后台、取消和销毁清理瞬时音源。设置单独存为 `underground-home.sound.v1` 的 `{ version: 1, muted }`，不更改世界存档版本；存储或设备不可用时游戏继续运行。

## 注意力交接

| 状态 | 当前关注对象 | 唯一主要操作 | 退出 | 完成后的交接 |
| --- | --- | --- | --- | --- |
| 声音切换 | 保留当前角色、建筑或目标 | 保留原主操作，声音按钮是常驻辅助入口 | 再点切换，无设置面板 | 留在原状态 |
| 挖掘 | 阿土与当前土块 | 当前挖掘委托 | 停下来、改选目标、撤销 | 挖开现场与既有发现/引导 |
| 建造 | 当前洞室或设施 | 当前建造操作 | 原有关闭/停止 | 设施完工与原有入住/下一目标 |
| 能源启动 | 能源核心，然后阿灯 | 沿用原有出场与逐句对话流程 | 先去探索/关闭/主动拖图 | 伙伴对话，然后原有小窝目标 |

未新增主要情境面板或主推进按钮。桌面声音入口显示文字；窄屏为带可访问名称和按下状态的 44px 图标按钮，与楼层导航同排，避免额外占一行地图空间。

## 验证

- `npm test`：40 个测试文件、412 个测试通过。新增音频生命周期测试，以及真实 App 在发现、对话、施工状态切换静音的注意力契约测试。
- `npm run build`：通过；仍有主包超过 500kB 的体积提示。
- `node docs/acceptance/audio-v1/verify.cjs`：独立 Chromium 上下文，1440×960、390×844；不使用玩家存档。
- 浏览器确认：用户手势解锁、开场静音/恢复/跳过、真实挖土与撤销、刷新后静音保留且不补播、能源入槽启动先于阿灯问候至少 600ms、开工无完工声而建成只播放一次、声音开关不关闭对话、没有页面错误。
- 已人工查看本目录的桌面对话、窄屏对话与建筑完工截图，检查按钮位置、主关注对象和角色遮挡。自动测试只确认时序和真实音频节点，不代表已经完成耳机/扬声器听感评审。

截图与机器结果：`1440-muted-conversation.png`、`390-muted-conversation.png`、`1440-building-complete.png`、`results.json`。

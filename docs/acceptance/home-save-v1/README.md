# 首页存档与更新记录验收

2026-10-20。按用户要求，进入页不再“每次都从头开始”：有浏览器存档时可以继续上次的家，并可从版本号打开游戏更新记录。

## 实际行为

- 进入页先读一次 IndexedDB。没有存档时显示“开始游戏”；有存档时主按钮变为“继续游戏”，下面一张小卡片写清三件事：上次玩到哪个任务、第一阶段第几步、上次保存时间（今天 / 昨天 / 月日）。
- 继续游戏直接回到读到的世界，不重播开场；新游戏才播 16.2 秒开场，按钮或 Esc 仍可跳过。
- 每做一件事按 350ms 防抖自动保存。只打开进入页、没有实际游玩时**不写新档**，避免下次凭空出现“继续游戏”。
- “重新开始”必须经过二次确认：说明上次的家会消失。取消后旧档和摘要都还在；确认后才清掉旧档、回到初始地图并重播开场。
- 存档读取失败时进入页直接显示原因，提供“重新开始”。失败期间不覆盖旧档；用户明确重新开始后才解除保护。
- 页脚显示 `开发试玩版 · v0.1.0`，点击打开“更新记录”。记录直接解析 `CHANGELOG.md`，不维护第二份文案，也不会把 Markdown 星号、链接语法露给孩子。Esc、点遮罩或“看完了”都能关闭。
- 900×620、390×844 下继续按钮、摘要、重新开始和版本入口都在视口内，没有横向滚动。

## 存档与版本

- 继续使用既有带版本号的 v12 存档（`underground-home-spring-playtest-v1` / `underground-home-save`），未新增存档字段，旧 v1–v12 档照常读取。
- 进入页摘要全部从世界数据推导：第一夜未完成时取当前主线；第一夜完成后切到“泉水与家园”的九步探索进度。
- 游戏版本仍取自 `package.json`（当前 0.1.0），没有在本轮擅自发布新版本号；更新记录里的“未发布”条目会原样显示。

## 实际验证

- `npm test`：**30 个文件、333 项通过**（首页存档那轮；后续伙伴与菜园调整后为 336 项）。
- `npm run build`：**类型检查与生产构建通过**；保留原有主包超过 500kB 提示。
- 生产预览：`http://127.0.0.1:5194/`，隔离 Chromium 上下文。
- 浏览器验证 8 组：新玩家进入页不写档、更新记录可读、挖一格后自动落盘、刷新出现继续游戏与 1/4 摘要、继续游戏不播开场且任务延续、重新开始取消/确认与清档、900×620 和 390×844 布局可达。
- 无页面运行时错误。结果见 [browser-report.json](browser-report.json)，复跑脚本为 [verify.cjs](verify.cjs)。

## 变更文件

- 新增 `src/app/saveSummary.ts`：进入页摘要与“今天 / 昨天 / 月日”时间文案。
- 新增 `src/app/releaseNotes.ts`：极简 CHANGELOG 解析，直接 `?raw` 读取仓库更新记录。
- 重写 `src/components/StartScreen.vue`：继续 / 开始 / 重新开始确认 / 更新记录弹窗 / 自动保存与不可保存提示。
- 修改 `src/App.vue`：注入 IndexedDB 存储、读取进入页摘要、区分继续与新游戏。
- 修改 `src/app/session.ts`：进入页状态、`startNewGame()`、空转不落盘、确认重开才清档；存档失败提示保留“不覆盖原档”。
- 修改 `src/core/history.ts`：重开时清空撤销栈，避免撤回到上一局。
- 新增 `tests/save-summary.test.ts`、`tests/release-notes.test.ts`，并在 `tests/session-exploration.test.ts` 增加继续、重开与损坏档恢复用例。
- 更新 README、CHANGELOG 与首轮进入页验收说明。

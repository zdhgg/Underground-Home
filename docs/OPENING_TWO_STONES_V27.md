# 开场点亮：两块能源石（存档 v27）

日期：2026-10-29。基线：`zcode/v1.2-ux2-home-wishes`（`39c48b5`）。

## 问题

第一层开场只要三次操作就能点亮家园：挖一格左门旁的能源石 → 点一下收好 → 点一下核心。七盏灯一次性亮完、阿灯出场、撒花全部发生在第一分钟里，后面的"给伙伴留床"反而成了更大的工作。点亮这件事发生得太快，孩子还没理解"电"是什么就已经结束了。

## 做法

**不加核心，加准备。** 点亮仍然是一次性的大演出（七盏灯依次亮 + 阿灯出场 + 撒花），但在它前面多了一块必须自己挖出来的能源石：

| 步骤 | 位置 | 玩家要做的 |
| --- | --- | --- |
| 1 | 左门旁 `(14,9)` | 挖一格，收好 |
| 2 | 大厅中间 | 点核心：只装进一块 → 核心哼一下、亮一点点，标签变成「还差一块」 |
| 3 | 右翼 `(26,11) → (26,10) → (26,9) → (27,9)` | 顺着大厅右墙挖开一列，再往右一格，收好第二块 |
| 4 | 大厅中间 | 再点核心：七盏灯全亮、阿灯出场、撒花，主线 3/4 |

开局操作从 3 次变成 9 次，但有四次不同的回报：石头露出来、核心先暖起来、第二块石头露出来、家园点亮。`主线` 仍然是 4 步，因为"修好核心"本来就是一个步骤；只是它内部多了一个"还差一块"的台阶。

### 为什么是"两块石头"而不是"两台核心"

- 同一台机器点三次是重复劳动；找两块石头是空间上的两件事。
- 三台核心并排会抢注意力，和"单一主要关注对象"冲突。
- 第二块石头在右翼，第一次把玩家带出大厅——右翼本来就是设计里留给客厅的位置。

## 位置与冲突

第二块石头放在 `(27,9)`，选这个格子是为了**不可能和任何建造打架**：

- 小床只铺下面两格（`y10–11`），石头在顶格 `y9`，压不到；
- `27` 是梯道保留列（`BREAKTHROUGHS`），任何房间都跨不过这一列；
- 客厅预设 `home-lounge` 从 `x28` 起，与石头相邻不相交；
- 菜槽、储物架、撤销挖掘都把两块石头列为保留格：`core/farm.ts`、`core/storage.ts`、`core/build.ts`（`canRestoreDig`）。

规则集中在新模块 `src/core/energyStones.ts`：石头列表、是否挖开、是否收好、下一块是哪块。`core/interact.ts` 的 `repairCore` 按顺序返回 `stage: 'loaded' | 'repaired'`，与世界状态匹配，先收哪块都不影响。

## 存档

`WORLD_VERSION` 26 → **27**，新增三个进度位：`secondCrystalFound`、`secondCrystalCollected`、`coreLoaded`。

旧档迁移：v26 及更早只要已经收好过一块石头（或已经点亮），就视为"旧要求已满足"，直接补成两块到手、核心已装，下一次点核心照常点亮——不在玩家半途加一道新功课。没有任何石头的旧档只是把新字段补成未完成。当前版本缺少新进度位按损坏处理。

## 验证

- `npm test`：**66 个文件、822 项测试通过**（新增 `tests/energy-stones.test.ts` 10 项：可达性、撤销保护、储物架/菜槽/睡眠舱/客厅预设不冲突、v26→v27 迁移）。
- `vue-tsc --noEmit` 与 `vite build` 通过。
- 生产构建 + Chrome 实机走了一遍完整开场：挖石头 → 收好 → 装第一块（微亮、「还差一块」、高亮转到右翼）→ 按指引挖开右翼一列 → 收好第二块 → 点亮（阿灯出场）。刷新后停在 3/4「给伙伴留床」，没有重播演出。
- 实机截图：`docs/acceptance/v1.3-two-stones/`（01 只装一块的微亮状态，02 点亮与阿灯）。

## 已知限制

- 只装了第一块时的亮度 `CORE_LOADED_LIGHT = 0.22` 是按"看得见核心、整间屋还暗"挑的，还需要儿童现场确认这个"半亮"是否被理解成"还没完成"。
- 第二块石头自己在 `y9` 顶格，需要按顺序挖开 `(26,11)(26,10)(26,9)` 才能站得住手；每一格阿土都会用"先挖开前面亮框里的土""小凳子上方还有土"给出下一步，但没有一次性的"一路挖到石头"委托。
- 第一块石头仍然是一挖即得；如果试玩发现开场整体还是偏短，下一步应该是加"准备"（例如核心需要一个从右翼挖出来的零件），而不是继续增加石头数量。

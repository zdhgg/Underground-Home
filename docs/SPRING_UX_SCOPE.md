# 第二层体验优化：连续施工、施工中断与突破反馈

基线：`670592d`（施工委托式操作试玩版）；分支：`codex/first-spring-breakthrough`。依据 AGENTS.md、GAME_BRIEF v0.5、PHASES 与 `docs/BUILDER_ORDERS_SCOPE.md`。本轮为同一分支上的体验优化，未发布、未合并。

## 要解决的三个问题

1. **连续破岩太啰嗦**：默认右侧梯道要连挖 6 段，每段都得重新点一次，孩子只在重复同一个动作。
2. **切后台 / 窗口失去前台时菜单里"阿土卡住"**：上一轮验收就记到"面板在后台时动画被节流，个别委托走路会停在半途并保持锁定提示，只能刷新"。原因是演出靠逐帧推进，而帧被冻结时没人来收尾。
3. **突破成果不够"大事"**：打通岩层、第一次下到第二层、发现泉水，反馈只有一句文字和一小团粒子，孩子感觉不到"我打通了新世界"。

## 1. 连续施工：前两段学、之后一口气挖到底

| 阶段 | 玩家要做的 |
| --- | --- |
| 破岩第 1、2 段 | 一段一次委托（学会"点目标 → 阿土自己走过去挖"） |
| 第 3 段起 | 小鼹鼠面板出现 **「⛏ 一路挖到底（还剩 N 段）」**；点它、或者继续点裂纹岩，都是一次挖到洞底 |

- 每一段仍然完整保留：真实走位 → 挥镐 → 落镐那一刻才破开 → 木梯同时接长一段，一段都不跳过。
- 链式施工期间画面给出**实时剩余段数**：洞口短语「一路挖到洞底（还剩 3 段）」+ 每条落地提示都带剩余数 + 按钮变成「阿土正在挖……（还剩 3 段）」。
- 规则层只加纯函数：`shaftDugSegments` / `shaftRemainingSegments` / `shaftChainReady`（`LEARN_SEGMENTS = 2`）。可用时机完全由地图推导，**没有新增存档字段**，刷新后仍然正确。
- 没有新增操作菜单：仍然是"指定目标，阿土执行"，只是同一句话在第 3 段之后一次性做完。

## 2. 施工中断：只取消、不改世界、立刻解锁

新增一条会话层的委托看门狗（`src/app/session.ts`）：

| 触发 | 处理 |
| --- | --- |
| 切到后台（`visibilitychange: hidden`） | 立刻 `abortOrder()`：清掉没播完的演出、阿土回到世界记录的位置、输入解锁；随后立刻落盘一份一致的存档 |
| 回到前台 | 补一句"怎么接着来"（链式施工会带剩余段数），并补写后台期间没落盘的一次改动 |
| 画面连续 3 秒没有新帧（窗口被遮挡 / 帧被冻结） | 判定"卡住了"，安全收尾并提示「⏸ 阿土停下来了，再点一次就好。」 |
| 画面还在出新帧、只是慢 | **不打断**（看门狗以"帧数有没有前进"为准，20 秒兜底） |
| 窗口失焦（blur） | 只复位指针手势，不打断施工（失焦不等于停帧） |

安全保证：演出只在**落镐那一刻**改世界，所以取消永远不会留下半成品、不会重复挖、不需要新增持久化字段。委托状态本身是会话内的临时状态，刷新即清空。

顺带修掉一个真实的"操作永久锁定"缺陷：`pointerControls` 原来只靠 `pointerup`/`pointercancel` 收尾，窗口失焦或指针捕获被系统收回时会把 `activePointerId` 一直挂住，之后**所有点击都被忽略**。现在增加了 `reset()`（同时监听 `lostpointercapture`），由会话在切后台 / 失焦时调用。

## 3. 突破、抵达与发现泉水的成就反馈

| 时刻 | 画面 | 声音 | 文案 / 卡片 |
| --- | --- | --- | --- |
| 岩层打通 | 镜头 0.9s 拉到能看全整条梯子的构图；水汽沿梯道往上冒；洞底大光环；阿土蹦起来喊「通啦！下面有水！」 | 低频崩塌声 + 更近的水声 | 里程碑卡片「⛏ 岩层打通啦！」 |
| 首次下到第二层 | 镜头缓动到泉水层；迷雾按列渐显；冷色洞壁、苔藓、小蘑菇露出；阿土喊「到啦！水就在那边。」 | 两音上行"到啦" | 里程碑卡片「🪜 抵达第 2 层 · 泉水层」 |
| 发现泉水 | 3 层水花 + 上飘水汽 + 白色小星 + 大光环；镜头轻推近水边；泉水从此常亮并逐帧泛波光；阿土喊「找到水啦！」 | 上行四音 + 一声水花 | 里程碑卡片「💧 发现地下泉水！」 |

- 里程碑卡片是新的 DOM 覆盖层（居中、3 秒自动收起、`pointer-events: none`），只做庆祝、不承载操作。
- 声音全部用 WebAudio 现场合成（`waterSound.ts`）：不联网、不加素材、不申请权限；没有音频设备时静默降级。挥镐也有一下轻轻的敲击+碎石声，连续施工时能听出一镐一镐的节奏。
- 美术仍是原有手绘卡通风格：新增的只有程序化图形（气泡、光环、波光）、相机运动与现有粒子/雾系统，没有替换素材。

## 最小修改范围

- **规则（core）**：`exploration.ts` 增加 `shaftDugSegments` / `shaftRemainingSegments` / `shaftChainReady` / `LEARN_SEGMENTS`（纯函数，不碰存档）。
- **会话（app）**：`session.ts` 增加委托生命周期（`beginOrder` / `abortOrder` / `watchdogTick`）、连续施工（`startChain` / `chainStep`）、`digToBottom()`、里程碑回调、消息去重、回到前台补写存档。**没有新增持久化字段，存档仍是 v5。**
- **输入（input）**：`pointerControls.ts` 返回值改为 `{ detach, reset }`，新增 `lostpointercapture` 复位。
- **画面（render）**：`explorationScene.ts` 增加 `cancel()` / `animating` / `react()`（阿土反应气泡+蹦跳）、剩余段数短语、泉水波光与"找到后常亮"；`PixiRenderer.ts` 增加 `cancelExplorationAnimation` / `explorationAnimating` / `frames` / `playMoleReaction` / `playBreakthrough` / `playSpringDiscovery` / `followShaft`（平滑跟随，不硬切镜头）。
- **界面（App.vue）**：连续施工按钮、里程碑卡片、图例与楼层提示文案。
- **文案（missions）**：破岩阶段的引导改成"练两次之后点「一路挖到底」"。

**不改动**：连续剖面与岩层蓝图、裂纹岩与梯子规则、任务链结构与完成判定、存档版本与存储键、自由挖掘 / 撤销 / 建造 / 楼层导航、美术素材、依赖清单。

## 风险与处理

| 检查发现 | 本轮处理 |
| --- | --- |
| 一次挖到底会让"逐段施工"的过程被跳过 | 链式施工仍然是每段真实走位 + 挥镐 + 梯子接长，只是不再需要重复点击；前两段仍必须手动委托 |
| 孩子可能在链式施工中乱点、插队 | 施工期间保持原输入锁，只给一句提示；落镐才改世界 |
| 切后台正好落在落镐瞬间 | 落镐回调本身是原子的（`dig` + 历史记录 + 落盘一次），取消只发生在没落镐时 |
| 取消后进度看起来"白挖了" | 取消不改世界，阿土回到记录位置，回到前台补一句"再点一次就好"，链式施工还会报剩余段数 |
| 慢设备上会不会把正常演出误判成卡死 | 看门狗看的是"帧数有没有前进"，慢但在动就不会打断；只有连续 3 秒完全没帧才收尾 |
| 后台期间防抖存档被节流，刷新丢进度 | 切后台立即 `persist()`；回到前台若还有未落盘的改动再补写一次 |
| 面板被宿主冻住（本轮实测环境）导致动画无法推进 | 实测正是这条：委托在 ~3 秒后自动收尾、世界不变、输入解锁——不再需要刷新页面 |

## 验证与回退

- 自动测试：`npm test` 145 项通过（新增：剩余段数/解锁时机、半挖梯道往返、一次点击连挖到底、切后台安全取消与回来接续、画面冻住时的看门狗、慢但在动不打断、渲染层取消不改世界）。
- `npm run build`：vue-tsc 类型检查 + Vite 生产构建通过。
- 实机验证与截图见 `docs/acceptance/spring-ux-v1/README.md`。
- 回退：本轮只改本分支。如需回退，链式施工只涉及 `session.ts` 的 `startChain`/`chainStep` 与 `App.vue` 的按钮（去掉即可回到逐段委托）；中断处理只涉及 `session.ts` 的委托生命周期与 `pointerControls.reset`；反馈部分可单独去掉里程碑卡片与新增音效，规则与存档不受影响。

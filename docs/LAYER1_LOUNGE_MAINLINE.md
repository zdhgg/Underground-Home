# 第一层客厅进主线（存档仍 v27）

日期：2026-10-29。基线：`282da32`（两块能源石）。

## 问题

客厅其实早就做完了——`RoomKind` 有 `lounge`、房间面板里有「客厅」按钮、预设洞室「暖暖客厅」在 `(28,9)`、石拱长椅茶桌两张手绘素材都接着、伙伴待命也会把客厅当集合点——但**主线里没有它**。跟着阿土走的孩子会：点亮 → 安床 → 听水声 → 换镐 → 挖通 → 下楼，客厅永远停在「还没建」。

结果就是第一层只剩"住处"一件事可做，二十来分钟就过去了。

## 做法

客厅成为主线第 5 步，排在**安床之后、下楼之前**：

| 主线 | 内容 |
| --- | --- |
| 1–3 | 能源石 ×2 → 修好核心（点亮） |
| 4 | 给伙伴留床 |
| **5** | **给家里留个一起坐的地方（客厅）** |
| → | 交给"楼下有谁在喊饿"，开始第二层的 12 步探索链 |

- 阿土的原话：`床安好啦！可是醒来以后，家里还没有一处能一起坐坐的地方。右边那个洞口再往里挖一挖，挖出一间小屋，摆上长椅和小茶桌吧。`
- 门口按钮在挖空前后分别是「看看要挖的客厅空间」和「修建暖暖客厅」；挖空时阿土会说"发现了暖暖客厅的旧痕迹"。
- 蓝图仍由阿土逐格清土、完工才扣材料（4 石料 + 2 旧木料），和两人小窝完全同一套流程。
- **不锁死选址**：`loungeBuilt()` 认预设洞室，也认自己挖出来、自由布置的客厅（任何 `kind === 'lounge'` 的已建房间）。
- **旧档不补课**：`loungeTaskDone()` 把"已经下到第二层"也算作这一步已完成。已经玩到楼下的存档不会突然被要求回头建一间它从来没被引导过的房子。

## 顺序是怎么保证的

引导层面而非规则层面：客厅没建好之前，阿土不会把目标交给"楼下有谁在喊饿"，`guideHighlight` 也不会指向裂纹。如果孩子自己找到裂纹并执意下楼，一次下去之后客厅这一步就自动完成，主线直接接到第二层——不制造"卡在客厅"的死锁。

## 验证

- `npm test`：**66 个文件、826 项测试通过**（新增 3 项：客厅出现在安床之后且高亮指向 `(28,9)`、自由选址的客厅也算、已下楼的旧档不补课）。
- `vue-tsc --noEmit` 与 `vite build` 通过。
- 生产构建实机：载入"刚安好床"的存档 → 引导卡显示「给家里留个一起坐的地方 · 4/5」，按钮「看看要挖的客厅空间」把镜头带到右翼并高亮 5×3；载入"客厅已挖空"的存档 → 按钮变成「修建暖暖客厅」，面板显示长椅茶桌图与 4 石料 / 2 旧木料，点「开工」建成；建好后主线立刻交接给「楼下有谁在喊饿 · 0/12」。截图见 `docs/acceptance/v1.3-lounge/`。

## 已知限制

- 客厅仍要 15 格手挖（5×3，和两人小窝的 9 格是同一套点一下挖一格）。如果试玩觉得太长，把预设改成 4 宽（12 格）是一行改动，美术本来就支持缩窄。
- 客厅建成后的"回报"仍然只有伙伴会去那里待命；更长的生活循环（待客、纪念、多人聚会）留在第四层的公共大厅和后续章节。
- 存档版本不变（v27）：客厅是否存在由 `builtSites` / `rooms` 推导，没有新增进度位。

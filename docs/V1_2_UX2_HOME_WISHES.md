# v1.2-UX2 · 我的家园心愿

> 开发分支 `zcode/v1.2-ux2-home-wishes` · 基线 `main` `009b19d` · 正式版本号仍为 v1.1.1 · 存档仍为 v26。不合并 main、不创建 Release。

## 1. 功能目标

九层主线告诉玩家“下一步可以探索什么”；家园心愿提醒玩家“以前建好的地方还可以做什么”。

本次只在阿土的探索小本子里增加一个可选的 **🏠 我的家园心愿** 栏目，位于“现在要做什么？”和“去哪里？”之间。它不是任务系统：

- 完全可选，不阻挡主线。
- 不领取、不提交、不显示奖励。
- 没有倒计时、连续完成或完成次数。
- 不保存心愿状态或历史。
- 只由当前 `WorldState` 推导，随真实世界变化自动出现和消失。

首批只有两种固定心愿，不扩展第三种，也不搭通用任务框架。

## 2. 两项心愿的出现条件

### 2.1 🪔 给小窝添盏暖光灯

显示文案：

- 标题：`给小窝添盏暖光灯`
- 说明：`第三层做的新部件，可以带回家啦！`
- 操作：`去看看小窝`

同时满足才出现：

1. `world.deep.completed === true`。
2. 第一层至少存在一间已建成小窝。
3. 第一层至少有一间小窝没有 `warmLamp`。

第一层判定不直接数 `world.pods`。`src/app/homeWishes.ts` 用现有 `podRect()` 和 `STRATA` 楼层边界，要求舱体顶行与底行都属于 `home` 层；大厅、花园、蓄水、听风等楼层的小窝不会被误判。

当第三层已完成但 `world.deep.parts === 0` 时，心愿仍然显示，并追加：

> 还差1个工坊部件，可以去第三层再做一个。

部件足够时不显示任何“材料充足”类文案，避免误导。

### 2.2 🥕 菜长熟啦！

显示文案：

- 标题：`菜长熟啦！`
- 说明：`小满照顾的菜可以收获啦！`
- 操作：`去看看菜园`

条件只有一条：当前世界里至少有一槽成熟作物。成熟判定直接复用 `src/core/farm.ts` 的 `ripePlanters(world)` 与 `RIPE_STAGE`；普通蔬菜和番茄共用同一条件，不建立第二套生长进度。

## 3. 点击后的定位规则

`GameSession.focusHomeWish(id)` 是唯一入口：

1. 先检查当前没有主要面板、伙伴工作、施工、建造/壁灯模式或共餐演出；有则只提示“先做完眼前这件事”，不取消任何工作。
2. 用**当前** `WorldState` 重新计算 `homeWishTarget()`，不相信界面上旧的 `podId` / 坐标。
3. 小窝：重新找仍存在、仍属第一层、仍未装灯的小窝；如果原来那间已经装好而另一间仍待改善，会自然改选当前有效目标。
4. 菜槽：重新找仍然 `growth >= RIPE_STAGE` 的真实菜槽，按稳定顺序选择；旧存档第一层菜槽也按实际坐标定位。
5. 复用现有 `renderer.focusOn()`；窄屏使用既有 `'building'` 上下文，把目标放到画面上部，避免被底部工具栏遮住。
6. 只移动镜头并给一句短提示，不调用 `installNestWarmLamp()`、`harvestPlanter()`、伙伴工作的 `request()`，也不写存档。
7. 目标已全部失效时不执行旧操作；提示“家园有变化：……”，并刷新心愿快照。

界面在点击后立即收起小本子，让出游戏画面。接下来是否装灯、是否收菜，仍由玩家点原来的小窝入口或菜槽决定。

## 4. 自动消失与重新出现

| 心愿 | 消失 | 重新出现 |
| --- | --- | --- |
| 暖光灯 | 全部第一层小窝都已有 `warmLamp`，或第一层没有小窝，或第三层尚未完成 | 又建了一间未装灯的第一层小窝；第三层完成；撤销暖光灯 |
| 收菜 | 最后一槽成熟作物被收获 | 任意菜槽再次长到 `RIPE_STAGE` |

心愿本身不记录“完成次数”，也不额外发放食物、部件、积分或成就。暖光灯仍用原有安装结算扣 1 个部件；收菜仍用原有小满工作与 `harvestPlanter()`。

## 5. 世界状态读取与同步

`src/app/homeWishes.ts` 是纯选择器：

```ts
homeWishes(world): HomeWish[]
homeWishTarget(world, id): HomeWishTarget | null
homeWishUnavailableReason(world, id): string
```

`HomeWish` 只含展示与定位所需字段：稳定 ID、标题、说明、按钮文案、目标、可选缺料提示。ID 只有 `nest-warm-lamp` 与 `ripe-planter`。

`src/app/session.ts` 在既有 `pushProgress()` 中发布 `hooks.onWishes(homeWishes(world))`。因此以下路径都不需要单独读浏览器存档：

- 第三层完成 / 章节结算后的原有 `pushProgress()`。
- 暖光灯真实安装完成、撤销。
- 伙伴收菜、浇水、种菜后的原有刷新。
- 玩家亲手干活导致作物长熟。
- 读取旧存档、重新载入游戏后的首次 `pushProgress()`。

界面只保存最新快照；点击时仍以当前世界为准，快照不是执行依据。

## 6. UI 集成

`ExplorerNotebook.vue` 新增 `wishes` 属性与 `wish` 事件：

- 顺序固定：主线 → 家园心愿 → 楼层导航。
- 有内容时才渲染整个 `section.notebook-wishes`；没有心愿时不留占位，也不显示“暂无心愿”。
- 最多两条；`HOME_WISH_LIMIT = 2`。
- 心愿是紧凑条目和浅色次要按钮；主线仍是唯一的醒目绿色大按钮。
- 心愿按钮不带 `data-primary-action`，不增加 `data-attention-panel`。
- `guideVisible` 为假（章节、房间、设施、伙伴工作、施工、设施面板等）时，心愿与主线一起从 DOM 移除；打开紧凑入口只看到楼层导航。
- 小本子宽度、顶部工具栏高度、Canvas 尺寸、镜头比例均未修改；窄屏仍默认收起；内容过多继续使用原有内部滚动。

`src/App.vue` 只新增 `wishes` 快照、`onWishes` 回调和 `@wish` 转发；点击时先收起小本子，再调用 `session.focusHomeWish()`。

## 7. 存档

本批次**不新增任何世界持久化字段**：

- 没有 `wishes`、`wishProgress`、`wishHistory`。
- `WORLD_VERSION` 保持 26。
- 存储键、IndexedDB 数据库名、序列化结构与旧档迁移均未修改。
- 心愿完全由世界状态重新计算，刷新或重进后不会出现“上次已完成但心愿还在”的独立任务状态。

## 9. 已知问题

1. 心愿快照仍由 `pushProgress()` 统一发布；以后新增世界变化路径时必须继续走这条刷新链，否则界面可能滞后。点击时会重新计算，因此不会执行过期操作，但栏目可能短暂显示旧内容。
2. 小本子里同时有主线、两条心愿和较多已开放楼层时，桌面端仍可能需要内部滚动；窄屏已压缩心愿区，390/360 首屏能看到“去哪里？”和第一条楼层入口。没有追加新的固定宽度或整页滚动。
3. 点击心愿只把镜头带到目标，不自动打开小窝详情或菜槽操作。这是本批次刻意保留的玩家决定权；若后续希望“一键打开对应入口”，需要另行确认交互层级。
4. 首版多间待改善小窝按 `pod.id` 稳定选第一间，不提供小窝选择弹窗；玩家定位后仍可点其他小窝。
5. 浏览器验收使用临时 IndexedDB 与无头 Chromium；没有改动正式存档、版本号或发布资产。

## 10. 合并前窄屏修订（2026-10-28）

本轮只处理两个手机端体验问题：心愿卡片过高，导致“去哪里？”被挤到内部滚动区下方；心愿按钮 38px 触控高度偏小。玩法规则、心愿触发、定位、结算、存档和版本号均未改动。

### 10.1 修改方式

`ExplorerNotebook.vue` 在 `max-width: 720px` 下：

- 心愿改为“图标＋短名称＋去看看”的横向条目；同时最多两条。
- 短名称只缩短措辞，不改变含义：
  - `🪔 小窝添盏暖光灯`
  - `🥕 菜长熟啦！`
- 普通说明文字在窄屏收起；桌面端继续完整显示。
- 材料不足提示不隐藏，放在对应心愿的第二行；实际材料检查、可点击状态和定位逻辑不变。
- 操作按钮最小高度改为 `44px`，左右内边距 `8px 12px`，`white-space: nowrap`，并保留 `:focus-visible` 轮廓。
- 移动端按钮可见文字统一为“去看看”，`aria-label` 仍使用完整文案：“去看看小窝”“去看看菜园”，屏幕阅读器可区分。
- 窄屏局部间距收紧：小本子头部上下内边距、区域间距、心愿列表间距；未改小本子最大高度（仍为舞台的 66%）、顶部工具栏高度、字号下限或楼层导航组件。

桌面端保持完整标题、说明和操作文案；心愿按钮同样提升到 44px。

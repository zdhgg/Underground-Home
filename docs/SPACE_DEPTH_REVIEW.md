# 空间结构与纵深玩法评估（设计评审 v1）

> 状态：**只做分析与建议，未实施**。本轮未修改任何代码、未新增依赖、未提交 Git。
> 输入：AGENTS.md、docs/GAME_BRIEF.md（基线 v0.5）、docs/PHASES.md、reference/first-night-v0.4.html、src/**（core / render / input / app）、tests/**、docs/acceptance/** 实景截图、docs/ART_PLAN.md。
> 结论针对"地下空间像一张二维平面、缺少楼层感与向下动力"这一试玩观察，不预设必须采纳分层方案。

---

## 0. 结论速览

1. **试玩感受是对的，但根因不是"缺楼层"。** 根因是三件事叠加：
   - **整个世界就是一屏**（44×29 格 = 1408×928 px，最小缩放 0.6 时整图只有 845×557 px，比常见舞台还小），玩家一眼看完，没有"往下"这个方向；
   - **纵深没有任何代价与回报差异**（挖左右和挖上下完全等价，越深没有新材料、新资源、新目标）；
   - **蓝图本身没有"层"**（全图只有 6 个被厚岩隔开的软土口袋，共 175 格可挖 = 13.7%；最大口袋 9×10；营地以外 68% 的格子是永不可动的填充岩石），所以房间没有真正的顶和底，设施像插在平面上的图标。
2. **不建议把 B1/B2/B3 做成引擎里的独立地图/场景**（切层加载、多套相机与存档）。这会毁掉"剖面一眼看懂整个家"的最大优势，且对 7 岁玩家是"要我记住哪层放了什么"的额外负担。
3. **建议的融合方案：一张连续剖面 + 命名地层带 + 层间厚岩盖层与弱岩突破口 + 可建造竖向交通（梯/电梯井）+ 分区照明。**
   玩家心智里的"楼层"由"深度尺 + 层名 + 每层主题与资源 + 电梯跳镜头"来提供；引擎里始终是一张图。这样既拿到"层层向下"的成就感，又保留完全自由的层内布局。
4. **顺手要解决的一个硬技术债**：地图一旦放大 2—3 倍，`core/build.ts` 的 `reachable()`（每次鼠标悬停都全图 BFS）与 `render/friendRoutes.ts` 的 O(n²) Dijkstra 会立刻变成卡顿源，必须在放大地图之前或同时改造（S1 内）。
5. **首章任务链不用推翻**，只需把"找泉水/建温室"从"往右 12 格"改成"往下 1—2 层"，并插入一个"打通盖层"的向下高潮，纵深就成立了。

## 1. 现状实测（代码与画面证据）

### 1.1 世界尺寸：整个游戏小于一屏

| 项目 | 数值 | 来源 |
|---|---|---|
| 地图 | 44 × 29 格 | `core/world.ts:19-20` |
| 像素尺寸 | 1408 × 928 | `render/camera.ts:22-23` |
| 缩放区间 | 0.6 – 2.2 | `camera.ts:16-17` |
| 0.6 倍时整图占屏 | **845 × 557 px** | 换算 |
| 相机约束 | 世界小于视口时**该轴居中** | `camera.ts:48-53` |

→ 在 1100×570 的典型舞台（见 `docs/acceptance/fixtures-v1/03-powered-home.png`）上，把镜头拉到最小，**整个地下家园完整地躺在一屏里，且四周还有留白**。这不是"地图很大但看不全"，而是"这个世界只有一屏"。玩家没有任何需要移动镜头才能抵达的地方——所以不存在"向下"这个体验。

### 1.2 地下内容只用了上半部分，其余是填充

从 `SOFT_POCKETS` / `CARVED_CAVES` / `LANDMARKS` 反推所有内容位置：

- 避难所大厅 y 7–11、竖井 y 4–7、能源石 (14,9)、能源核心 (21,9)、睡眠舱口袋 y 7–12；
- **地下泉水 (31,15)、温室口袋 y 7–16、最低软土 y 17–18**；
- **y 19–28（10 行）没有任何内容**，y 16 以下也几乎只有传送带式的两块小口袋。

即：**全部剧情与可玩空间集中在 12 行（约半屏）的横带里，地图下半部分是纯岩石填充。**

### 1.3 故事说"向下"，几何却是"向右"

基线 v0.5 第一夜明确写"挖出可用的睡眠舱空间，**向下**发现天然泉水"。实际几何：

- 能源核心 (21,9) → 泉水 (31,15)：**右移 10 格、下移 6 格（192 px）**。核心概念上"往下探索一层"，实现上是"往右挪半屏"。
- 顶灯、伙伴、睡眠舱、泉水全部在同一视觉横带内，玩家不可能产生"我下去了一层"的判断。

### 1.4 蓝图没有"层"，房间没有顶和底

- 6 个软土口袋是**互相被厚岩隔开的孤岛**（9×6 / 9×10 / 4×4 / 5×2 / 2×4 / 3×2），玩家不能挖岩石，所以也**无法把两个口袋连起来**，只能在各岛屿内部啃。
- 全图 **只有 175 格可挖（13.7%）**，872 格岩石（68%）在整个首章里既不可挖也没有语义差别。
- 睡眠舱 3×2：最小口袋 5×2 只能放 1 间，最大口袋 9×10 约放 2–3 间。玩家无法"规划一整层"。
- 因为口袋上下都是同一片岩石，"房间"在视觉上更像贴在平面上的图标，而不是从岩层里掏出来的空间——这正是"二维平面地图"感受的直接来源。

### 1.5 岩石升级解锁在当前蓝图上无法产生"向下"

AGENTS.md 与基线都写了"岩石暂不可挖，后期由工具升级解锁"。但当前岩石**处处同质**（872 格全是一种岩）。因此"解锁岩石"只会解锁**更多横向的同质空间**，包括地图最底部——它天然无法表达"更深 = 新的、更值得的、需要更高工具等级的地层"。**纵深的语义必须在蓝图里先存在，工具升级才有的可解。**

### 1.6 居民、交通与建筑

- 两位伙伴起点在 `PixiRenderer.rebuildFriends` 中**硬编码** 18.6 / 23.9 格 × TILE_SIZE；同坐标又有一份 `FRIEND_HOME_CELLS` 只被测试使用（`render/friendRoutes.ts:8`），属重复来源。
- 伙伴的全部行为 = 站着弹跳 + 一次性入舱演出（`playPodEntrance`，约 120 行，含错峰、爬墙贴壁、上床）。入舱后永久睡眠，无设施使用、无上下层行为。
- 竖向交通只有**竖井木梯**一处地标（`LANDMARKS.shaft` + `isLadderCell` 硬编码该矩形），且对玩家本身没有功能意义——**玩家没有角色化身**，镜头靠拖动平移，梯子只服务伙伴路径。
- 全局只有**一个** `lightLevel`，黑暗遮罩是盖住整个地下的**一整块矩形**（`PixiRenderer.drawLighting`），所以"点亮"是全图一次性事件，不可能有"点亮某一层"。

### 1.7 任务与硬编码耦合

- `missions.guideHighlight` 只覆盖"挖/收/修"三阶段，核心修好后返回 `none`；
- 建造阶段的引导目标写在 **session.ts 里的魔法矩形 `{ x: 11, y: 7, w: 6, h: 5 }`**（`src/app/session.ts:392`）；
- `pushProgress` 里另有 `pendingRest` 特判与任务文案耦合。
→ 任务系统目前无法表达"下一层"这种空间概念，加层会让硬编码进一步发散。

## 2. 问题诊断（6 条）

1. **尺度问题（最根本）**：世界小于一屏，没有"远方"，也就没有"更深"。纵深是尺度的产物，不是层数的产物。
2. **方向无差异**：挖掘的代价与回报与方向无关；越深没有新材料、新资源、新风险、新光照状态。
3. **空间无层级**：没有"层"的语义单位（命名带、盖层、层内主题），房间没有岩石顶/底，设施缺少"嵌入岩层"的语境（睡眠舱已是嵌入造型，方向正确，但孤例）。
4. **交通无意义**：玩家无化身 → 竖向交通必须靠"居民使用 + 设施功能 + 镜头导航"三者证明存在价值，目前只有一处装饰性竖井。
5. **生长方向没出口**：同质岩石让"工具升级解锁"只能横向铺开，无法承载"下一章更深处"的期待。
6. **工程债**：全图 BFS（每次悬停）、O(n²) Dijkstra、地图尺寸写死在 `persistence.ts` 校验与 `camera.ts` 常量、任务锚点硬编码——都是"放大地图"会立刻踩到的雷。

## 3. 分层方案评估：B1/B2/B3 该不该做

### 3.1 用户设想中正确的部分

- **"逐层开放"作为进度轴**：非常符合 7 岁玩家的"新区域 = 奖励"心智，也符合基线"建立下一次向下拓展的期待"。
- **"层内自由挖掘和建设"**：保住了自由建造的核心，没有被任务锁死布局。
- **"地下交通"作为独立系统**：确实是当前最缺的一块体验。

### 3.2 我不建议的部分：把层做成独立地图/场景

| 代价 | 说明 |
|---|---|
| 丢掉最大优势 | 横截面游戏的全部魅力是"一眼看见我的家从地表长到深处"。切层后每次只能看到 1/3，"堡垒全景"消失，P3 的结尾全景庆祝也随之失去意义。 |
| 增加儿童负担 | 7 岁玩家要在脑内维护"温室在二层、床在一层、泉在三层"的抽象索引；一旦找不到，就是挫败而不是探索。 |
| 状态与迁移成本翻倍 | 世界状态要按层拆分，存档要分层版本化，相机/输入/撤销/任务高亮全部要按层重做，且旧存档必然作废。 |
| 与现有美术方向冲突 | 已接入的岩层剖面 PNG、嵌入洞壁的睡眠舱、竖井木梯，全部建立在"连续剖面"的视觉语言上。 |
| 仍然不解决"没有向下感" | 如果每层还是一屏大小、内容是 6 个软土口袋，切层只是把同一张平面图切成三份，问题原样保留。 |

### 3.3 建议方案：一张连续剖面 + 地层带（融合方案）

**把一个"层"定义为地图上的一条命名横带（stratum band），而不是一张独立地图。**

```
深度尺（玩家可见）                引擎内部
─────────────────────────        ─────────────────────────
  ☀ 地表 0 米                     y 0–4   天空 + 地表
  🏠 第 1 层 · 暖窝（居住）        y 5–16  软土带：避难所、能源石、睡眠舱
  ▓▓ 岩盖层（含 2–3 处弱岩带）      y 17–19 硬岩：把两层真正隔开
  💧 第 2 层 · 水层（生产）        y 20–33 砂岩/黏土带：泉水、水塔、水培温室
  ▓▓ 岩盖层（含 2–3 处弱岩带）      y 34–36 硬岩
  ✨ 第 3 层 · 深岩（能源/探索）    y 37–52 深岩带：晶簇、地热裂隙（下一章）
  ▓▓ 基岩                         y 53–57 本章不可挖
```

- 世界放大到约 **64 宽 × 58 高（3 屏高、约 2 屏宽）**，但**仍然是一张连续地图**；
- 每条软土带内部**不规则**（连续大口袋 + 岩石侵入体），保证"层内完全自由"；
- 两条岩盖层是**厚岩**，只在 2–3 处留"弱岩带"（有裂纹/异色，工具升级后可挖）→ 向下是有代价、有选择、有高潮的；
- "楼层"感由四个便宜的东西提供：**深度尺 + 层名 + 每层主题资源 + 电梯跳镜头**。

### 3.4 什么情况下才该做真正的多图层

只有当**目标平台是竖屏手机、且一层的面积就等于一屏**时才成立（把"一层"当成一关来做，靠电梯做加载点）。如果后续确定要上竖屏手机，**更推荐的做法仍是同一张地图 + 电梯把镜头吸附到离散的层位**——玩家感受是"按电梯下楼"，引擎里没有第二张图。这是"分层体验"与"单图实现"的最优折中。

### 3.5 "层"的命名建议（给 7 岁）

不要用 B1/B2/B3。用**功能 + 米数**：

| 层 | 名字 | 主题 | 关键发现物 | 主要建造 |
|---|---|---|---|---|
| 1 | 暖窝层（约 -4 米） | 居住 | 能源石 | 睡眠舱、储藏、层灯 |
| 2 | 水层（约 -22 米） | 生产 | 地下泉水 | 水塔/水泵、水培温室、层灯 |
| 3 | 亮晶晶层（约 -40 米） | 能源与探索 | 晶簇、地热 | 钻机、电缆、下一章 |

> 孩子对"往下多少米"的直觉远强于对 B1/B2/B3 的直觉。深度尺上一句"你在这里"就够了。

## 4. 四个问题的回答

### 4.1 如何兼顾 7 岁儿童的操作能力

- **不增加任何新手势**：仍是"单击挖一格 + 拖动平移 + 建造预览 + 确认/取消 + 撤销"。已有的 `gesture.ts` 点击/拖动阈值判定直接复用。
- **放大世界带来的唯一新增风险是"迷路"**，必须与放大同时交付：
  1. **深度尺**（左侧 DOM 覆盖层）：显示各层名字与深度，标出"家"的范围与"你正在看这里"；
  2. **自家高亮**：已建成区域在地图边缘/缩略图上有一点常驻标记；
  3. **电梯/竖井 = 一键跳层**（把"回到家园"按钮升级为"回家 / 去水层"这类**至多 3 个**目标，而不是自由选层）。
- **一次只给一个目标**：现有"阿土一句话 + 高亮 + 带我去看看"的克制做得对，扩层后要保持——高亮指向**下一处弱岩带**而不是整条盖层。
- **长流程拆小步**：打通盖层至少分"找到弱岩带 → 升级工具 → 打通"三次明确反馈，避免"挖很久没变化"。

### 4.2 如何兼顾闯关目标（任务）

- 任务链不推翻，只**把位置语义从"左右"改成"上下"**，并插入一次向下高潮。建议 7 步（每步都保留"为什么 / 做什么 / 会怎样"）：

  1. 挖开泥土找到能源石（现有）
  2. 收好能源石（现有）
  3. 修好能源核心，**点亮第 1 层**（现有，"点亮"改为分层语义）
  4. 在第 1 层挖出空间并安放睡眠舱（现有）
  5. **顺着阿土指的方向往下挖，找到岩盖层上的"弱岩带"**（新；高亮 2–3 处可选，不指定唯一路线）
  6. **升级铁镐，打通到第 2 层**（新；第一次"层层向下"的高潮：突破瞬间的碎屑/回响/镜头下移）
  7. 第 2 层：**找到泉水 → 建水塔 → 建水培温室 → 浇水 → 收获**（P3 内容下移一层）
  8. **建"层灯"点亮第 2 层** → 第一夜完成（黑暗退去 + 全景庆祝，深度尺上出现第 2 层）

- **解锁用"发现物"，不引入资源计数**：首章继续"粗版不消耗建造资源"，工具升级靠发现晶簇/找到弱岩带触发。这比"攒 20 个石头"更适合 7 岁，也与现有单调 `progress` 位完全同构。
- **任务锚点必须跟数据走**：把"高亮/居中目标"写进任务定义（替换 session.ts 的魔法矩形），否则每次改蓝图都会指向错地方。

### 4.3 如何保住自由建造的乐趣

- **层内保持完全自由**：软土带做成连续大口袋 + 随机岩石侵入，玩家爱怎么掏怎么掏；任务只规定"这一层要解决的问题"，不规定房间位置与形状。
- **自由度的真实瓶颈是"可挖格数 + 承托规则"**，不是口袋形状。放大世界后应把可挖面积从 175 格提到 **800–1200 格**量级，同时保留"设施必须坐在实心地面上、门要连通家园"这两条简单规则（孩子可预测、可解释）。
- **设施从"一个睡眠舱"变成一族同构条目**：占地、承托、连通、唯一通路这四条校验对睡眠舱 / 层灯 / 电梯 / 水塔 / 温室完全一致，用一张数据表 + 一个校验器（现在这些规则全写在 `canPlacePod` 里）。
- **撤销必须覆盖新增的建造物**：`core/history.ts` 的 action 联合类型已经支持扩展（`{kind:'dig'} | {kind:'pod'}`），加 `'facility'` 即可，保护谓词机制原样复用。

### 4.4 如何让居民、建筑与生态真正"地下堡垒"

**（1）居民：不做 AI，把已有的"一次性演出"参数化。**

`playPodEntrance` 已经实现了本游戏需要的 80%：错峰出发（`ENTRANCE_STAGGER`）、按真实空洞格寻路、爬墙贴壁、落位呼吸。把它从"去睡眠舱"泛化成"去某个设施使用"，每个设施只需声明四个数据：`useSpot`（站位）、`pose`（动作）、`duration`、`from`（优先从哪来）。于是：

- 建成温室 → 伙伴自己走过去浇水（叶子可见生长）；
- 建成电梯 → 伙伴走到井口、乘电梯到第 2 层（**上下楼成为可见行为**，这是"地下堡垒"最核心的一条）；
- 晚上 → 各自回舱睡觉（现有行为）。

观感上就是"这里有生活"，而代码只增加一张表。**这比引入复杂居民 AI 更省，也更符合基线"暂缓复杂居民 AI"。**

**（2）建筑功能：让每个设施"与地层绑定"。**

| 系统 | 代表设施 | 视觉/机制要求 |
|---|---|---|
| 居住 | 睡眠舱（已有） | 嵌入洞壁（已是正解，继续） |
| 行 | 木梯（可叠）、**电梯井/吊篮** | 电梯井贯穿多层，是全家的交通枢纽与视觉中心；点电梯 = 镜头跳层 |
| 电 | 层灯 / 配电箱 | 每层一盏，接通后该层亮起（见 4.5） |
| 水 | 水塔 / 水泵 | 从水层往上层送水，水管可见 |
| 食 | 水培温室（P3） | 生长 → 收获，全部放进第 2 层 |

**（3）生态：首章只做一条可见的链，但必须是"跨层"的。**

```
第 2 层泉水 → 水泵/水塔 → 水管 → 温室 → 收成 → 伙伴去浇水/收获
```
跨层是重点：生态链一旦跨层，玩家就有了"上下跑"的真实理由，纵深从"景观"变成"系统"。

**（4）照明：把"点亮"从一次性事件改成按层发生（性价比最高的改动）。**

- 现状：一个 `lightLevel` + 整块黑暗矩形 → 全图一起亮。
- 建议：`world.litBands: Set<bandId>`（或每层一个布尔），黑暗遮罩按带绘制；每层首次点亮沿用现有的"顶灯依次亮起 + 撒花 + 镜头拉开"演出（`lampFixtures` / `pendingCelebration` / `computeRepairShowcase` 全部可复用，只是作用范围从"全图"变成"这一层"）。
- 收益：玩家每次向下都会经历"黑暗 → 我发现东西 → 我建造 → 这一层亮起来"的完整闭环。**"层层向下的成就感"其实主要来自这个闭环，而不是楼层编号。**

## 5. 目标设计的建议数值

| 项目 | 现值 | 建议值 | 理由 |
|---|---|---|---|
| 地图 | 44×29（1 屏） | **约 64×58（≈3 屏高、2 屏宽）** | 向下 2 层需要真实行程；仍可一屏看到"一层" |
| 地表行 | y=4 | y=5 | 留出地表视觉余量 |
| 软土带 | 6 个孤立口袋 | **3 条连续带 + 岩石侵入体** | 层内自由、层间有隔 |
| 岩盖层 | 无 | 2 条厚盖层（各 3 行）+ 每条 2–3 处弱岩带 | 向下的代价与选择 |
| 可挖格 | 175（13.7%） | **800–1200** | 自由建造的真实空间 |
| 缩放 | 0.6–2.2 | 0.7–2.2 | 阻止"一眼看完全图" |
| 地层材质 | 2 种（土/岩） | **4–6 种**（表土/黏土/砂岩/弱岩/深岩/基岩，各 1 个有用矿脉变体） | 深度可读、工具分级有意义 |
| 光线状态 | 1 个全局值 | **按层独立 + 可建造层灯** | "点亮这一层"成为每层的高潮 |
| 存档 | v3，尺寸写死校验 | **v4**：世界尺寸入档、工具等级、点亮层、多类设施；瓦片可 RLE | 尺寸变化必然要迁移 |

> 世界尺寸三倍化 ≈ 可挖格 5–7 倍 ≈ 3–4 小时的首章内容量，对 7 岁儿童是合理的单章体量（当前内容约 30–40 分钟就用尽沙盒）。

## 7. 分阶段实施建议（每阶段可独立验收、可回退）

### S0 · 蓝图试点：先验证"纵深可读性"（最小成本，强烈建议先做）
- **做什么**：只改蓝图数据——世界加高到 2 屏（如 44×46），把内容改成"第 1 层（现有 4 步）+ 厚岩盖层 + 一条下沉带（泉水/温室下移）"；**规则、任务、渲染都不动**（只更新 `LANDMARKS`、口袋矩形、尺寸常量与 `world.test` 快照）。
- **验收**：给孩子看 10 秒，问"这个家有几层"，能回答"两层"；老玩家不读教程仍能走完第一夜。
- **代价**：旧存档因尺寸校验失效（提示"已开始新的第一夜"），需确认接受开发期重置。
- **价值**：用 1 天验证整个方向是否正确，避免在错误的假设上投入 S1–S4。

### S1 · 材质与工具分层 + 修掉放大就会爆的性能债
- `TILE` → 材质表；`dig` 按"工具等级 vs 硬度"判定；`progress` 增加 `toolLevel`。
- 岩盖层 + 弱岩带进入蓝图；任务插入"找到弱岩带 → 升级 → 打通"。
- **同时**改造 `reachable()`（预计算连通分量）与 `nav`（A*），因为放大地图后这两处是全图级开销。
- **验收**：单测覆盖"工具不足不可挖 / 升级后可挖"；实机打通盖层，悬停预览不掉帧。

### S2 · 分区照明与"点亮这一层"
- `lightLevel` → 按层状态；黑暗遮罩按带绘制；新增可建造"层灯"，接通后该层亮起并复现现有庆祝演出。
- **验收**：挖到第 2 层时是黑的；建成层灯后整层亮起、播放庆祝、刷新后保持。

### S3 · 竖向交通 + 居民使用（"地下交通"落地）
- 可建造木梯（可叠）、电梯井/吊篮（点击跳层，成为玩家导航手段）。
- 居民行为从"一次性入舱"泛化为"去设施使用"（`useSpot / pose / duration / from`），伙伴可乘电梯上下、去温室浇水、晚上回舱。
- **验收**：建成电梯后，伙伴自主乘电梯往返两层并使用设施；无需持续 AI 模拟。

### S4 · 设施通用化 + 第二层生态 + 存档 v4
- 设施表 + 统一放置校验（睡眠舱/层灯/电梯/水塔/温室同构）；撤销覆盖全部设施。
- 泉水 → 水塔 → 水管的跨层供水链 + 温室生长收获。
- 存档 v4（世界尺寸入档、工具等级、点亮层、设施列表，必要时瓦片 RLE），并给出 v3 → v4 迁移提示文案。
- **验收**：在第 2 层自由规划水塔 + 温室，规则一致、可撤销、刷新后完整恢复；`npm test` 全绿。

> 每个阶段结束都应保持"可运行、可构建、可测试"，并按项目惯例提交中文 conventional 提交信息（S0 的蓝图改动建议单独一个提交，便于回退）。

## 8. 风险与"不做"清单

**风险**
1. **迷路**（放大世界的主要成本）：必须与 S0/S1 同时交付深度尺 + 自家高亮 + 最多 3 个跳转目标，绝不能只放大空间。
2. **精灵数量**：64×58 全量 = 约 1.9 万精灵；需区块化 + 视口裁剪，并在目标设备（孩子用的那台平板）先做一次帧率探针。
3. **存档断裂**：地图尺寸变化必然让 v3 存档失效，迁移策略要提前定（建议"保留进度位、重置地图"并明确提示）。
4. **硬编码蔓延**：现有 4 处任务/引导硬编码（crystalZone、generatorZone、shaft、session 魔法矩形）必须随蓝图一起数据化，否则每次改图都会指向错目标。
5. **演出与数据不一致**：`friendRoutes` 与渲染层各存一份伙伴坐标；泛化前先合并到 `core/nav.ts` 单一来源。

**明确不做**
- 不做 B1/B2/B3 独立地图/切层加载（若要上竖屏手机，用"电梯吸附镜头"代替）。
- 不做随机生成地图（基线已暂缓"无限随机地图"）；分层蓝图继续手工设计，保证任务引导可靠。
- 不做持续居民 AI / 寻路模拟；继续"一次性演出参数化"的低成本路线。
- 不引入建造资源计数与库存（首章保持"发现物解锁"，更符合 7 岁与现有实现）。
- 不做战斗、复杂承重、流体模拟（基线已暂缓，与本议题无关）。

## 9. 需要拍板的决策

1. **目标平台与方向**：桌面/平板横屏为主，还是必须支持竖屏手机？（决定"电梯吸附镜头"要不要做，以及世界宽度）
2. **世界放大幅度**：建议 64×58（3 屏高）；是否接受把首章内容量扩到 3–4 小时。
3. **开发期存档**：接受"放大地图后旧存档重置（保留进度位）"吗？
4. **是否先做 S0**（纯蓝图试点，1 天，验证"纵深可读性"后再投入系统改造）。

> 我的倾向：**先做 S0**。它成本最低，且能同时验证"我们说的层，孩子是否真的看得见"——这件事一旦不成立，S1–S4 的技术投入都应重新评估。
